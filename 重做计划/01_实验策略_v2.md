## 0. 把研究问题定成一句话

> **在不能调用外部大模型、标注成本高的前提下，能否只用「可验证的奖励」（数学/几何金标），从基座模型直接 RL，拿到接近「教师标注 SFT」的分数？**

mentor 的原始表述是：基座 20 分 → 教师标注 SFT 80 分 → 如果「直接 RL」能到 70 分就算成功。
本文件把这句口语化的目标翻译成**冻结基准上的、可判真假的判据**，并且指出这个目标的一个新事实。

## 1. 目标的重新校准（这一步必须先做，否则后面的实验会答错题）

### 1.1 分数刻度对齐

本项目已有的刻度：基座零样本 **0.2143**，教师标注 SFT **0.6230**（252 行基准的分类准确率）**[记录]**。
mentor 的「20 → 80」与本项目的 21.4 → 62.3 同形，所以「70 分」≈ **0.87 × SFT ≈ 0.545 准确率**。

**→ 判据 P：RL-only 在冻结基准 252 行上的分类准确率 ≥ 0.545，且成对检验（McNemar）不能拒绝「等于 SFT」。**

### 1.2 但今天测出的一个事实，改变了这条判据的性质

**[实测]** 只用 31 维确定性几何特征（缺陷比例、质心/平均半径、径向 10 bin、角度 12 扇区、合成向量长度、角度熵、各向异性比）做一个**最近质心**分类器，用 train 划分拟合质心。

**统一在冻结基准 251 行上测**（按 lot 分层抽 k 个标注，5 个种子取均值）：

| 拟合用多少标注 | 基准 251 行准确率 | 5 种子范围 |
|---|---|---|
| 50 | 0.4916 | 0.4622 ~ 0.5259 |
| 200 | 0.5761 | 0.5578 ~ 0.5896 |
| 1000 | 0.6096 | 0.5896 ~ 0.6215 |
| 全部 train（4720） | **0.6693** | — |

而教师标注 SFT 在同一批行上是 **0.6230**。

> ⚠️ **2026-09-27 订正**：本节初稿记的是「50 → 0.5051、200 → 0.6088、1000 → 0.6412、全部 → 0.6531（test 589 行）」，
> 并单独给出「基准 252 行 = 0.6693」。**那组数字的逐类召回无法复现**（初稿记 Loc 0.24 / Random 0.82，
> 用四种分类器、三种归一化都复现不出来）。现在改为**单一口径**：全部在基准 251 行上测，按 lot 分层抽样。
> 头条结论 **0.6693 精确复现**，方向性结论（哪几类几何判不出）不变，但**具体数值以本表为准**。
> 复算脚本见 `学习记录/几何verifier复算_20260927.md`。

**这意味着两件事，必须同时说：**

1. **mentor 的方法在原理上可行** —— 类别信息**主要就在几何里**，不需要教师也能拿到 0.6 以上。
2. **但「RL 达到 70 分」这个成功，不能证明 RL 学到了视觉理解** —— 一个不带任何图像语义的几何分类器已经超过了 SFT。所以判据 P 必须配一条守卫判据。

**→ 守卫判据 Q：RL-only 必须在「几何特征不足以判别的类」上有提升。**

**[实测]** 几何分类器（全部 train 拟合）在基准 251 行上的**逐类召回**：

| 类 | 召回 | 类 | 召回 |
|---|---|---|---|
| Near_full | **1.00** | Edge_Loc | 0.63 |
| Donut | **0.97** | **Loc** | **0.40** |
| Center | 0.90 | **Scratch** | **0.33** |
| Edge_Ring | 0.87 | **none** | **0.32** |
| Random | 0.70 | | |

**Loc（0.40）、Scratch（0.33）、none（0.32）就是「几何判别不出、必须看图」的类。**
如果 RL-only 只在这三类之外的类上涨，那它涨的是 verifier 的功劳，不是模型学会了看图。

### 1.3 评测场景：主榜 + 鲁棒榜（2026-09-27 新增）

**问题**：现基准的请求只有 `user` 一条消息（`benchmark.py:187`），
而训练时是 `system + user` 两条（`curate.py:268-272`）。
同一个 SFT 模型：考卷问法 0.6230 / 训练问法 0.8849（`docs/LIMITATIONS.md` §6.4）。
**两处差异叠在一起，哪一处造成差距未测。**

**新方案要求：基准跑两遍，分开报。**

| 榜单 | 场景 | 回答什么问题 | 禁止用途 |
|---|---|---|---|
| **主榜** | 与训练**完全一致**（带 system、同措辞） | 模型学会看图答题了吗 | 不得用于说明"能不能上生产"（会高估） |
| **鲁棒榜** | 陌生场景（不带 system / 换措辞） | 能不能在控制不了的问法下也不崩 | 不得用于说明"模型能力"（会低估） |

**报分数时必须注明场景。**

**连带问题（需要在方案讨论里定）**：已有 **12 run × 16 指标**全部是考卷问法下测的，
而训练格式的诊断**只做过 SFT 一个模型**。所以要么 12 个 run 全部重跑，
要么**保留现有数字作为"陌生场景榜"、另补一套"训练场景榜"**，两套并存。

详见 `学习记录/评测场景一致性_20260927.md`。

### 1.4 判据的完整形式（建议写进给 mentor 的一页纸）

| 判据 | 内容 | 若成立说明什么 |
|---|---|---|
| **P（主）** | RL-only（零标注）在冻结基准上 ≥ 0.545 | mentor 的目标达成 |
| **Q（守卫）** | **见 §1.5** —— 增量必须落在 H 集上 | 增益不是纯几何 verifier 的 |
| **R（成本）** | 标注预算曲线：k 个标注时 RL 到多少，k 是多少时才追平 SFT | 直接回答「标注贵不贵」 |
| **S（诚实）** | 报告几何 verifier 自身的分数作为成本下界基线 | 防止把 verifier 的分数记在 RL 头上 |

### 1.5 判据 Q 的升级版（2026-09-27 新增，取代原来「三类至少一类上升」的写法）

**旧写法的问题**：`Loc / Scratch / none 三类里至少一类召回上升`——门槛太松（碰巧涨一类概率不低），
而且**按类聚合**的召回会因为该类整体难度波动而误判。

**新写法：把基准拆成两个子集，看增量落在哪。**

先用几何 verifier（乙）逐行判一遍基准 251 行，按它答对/答错切开：

| 子集 | 行数 | 含义 |
|---|---|---|
| **E 集**（乙答对） | **168** | 光靠量 31 个数字就能答对的题 |
| **H 集**（乙答错） | **83** | 乙答不对的题 —— **只有在这里也涨，才说明 RL 学到了几何之外的东西** |

**→ 判据 Q（升级版）**：分别报告 RL 相对**基座**在两个子集上的增量。

- 增量**只在 E 集** → RL 是做了一遍"乙"做的事，**换了个实现方式而已**，没有引入几何之外的信息
- 增量**在 H 集上也有**（且成对检验显著）→ RL 提供了几何之外的信息，**才有资格说"学会了看"**

**H 集的构成**（同一批 251 行）：

| 类别 | H 集中该类的数量 | 占该类比例 |
|---|---|---|
| Scratch | 20 | 67% |
| none | 17 | 68% |
| Loc | 18 | 60% |
| Edge_Loc | 11 | 37% |
| Random | 9 | 30% |
| Edge_Ring / Center / Donut | 4 / 3 / 1 | 13% / 10% / 3% |

**H 集里 55/83（66%）来自 Scratch、none、Loc 三类**，与原判据的直觉一致；但升级版把它们变成了**逐行可算的分母**。

**这个判据的三个已知限制（必须写进报告）**：

1. **H 只有 83 行，样本量小** —— 任何增量都要报置信区间，不能只看点估计。
2. **「乙答错」≠「必须看图」** —— 可能只是那 31 个数字不够好。也许换一套更强的几何判据就能判对。**这是这个判据最大的软肋。**
3. **H 里混着 Edge_Loc（11 个）**，不纯是"必须看图"的题，报告时要拆开看。

## 2. 三个前置测量（先做，都在几十分钟内，决定后面的 GPU 值不值得花）

### M1 — verifier 的天花板（部分已完成）

- **[实测]** 用标注拟合的几何 verifier：k=50 → 0.4916、k=200 → 0.5761、k=1000 → 0.6096、全部 train → **0.6693**（基准 251 行，lot 分层，5 种子）。复算见 `学习记录/几何verifier复算_20260927.md`。
- **[待测]** **零标注**版本：纯手写领域规则（不拟合任何标签）。做法：按 `radial_density` 的形状、`resultant_length`、`anisotropy_min_over_max`、`defect_extent_r` 写 5–9 条 if-else，先在一张 20 行的草稿上把规则读通，再到 252 行上测。
  **它给出「一个标注都不用」的分数下界。** 如果它就有 0.5+，那 mentor 的成本论点会被这条直接坐实。
- **[待测]** 每一类的 verifier 精度 —— 因为 GRPO 的奖励是**逐样本**给分，verifier 在 Loc 上的 0.24 会让那些样本拿到错误奖励，把模型往错的方向推。

### M2 — 基座的 pass@k（观察正确答案在多次回答中是否出现）

用 `temperature=1` 对 252 行各采 N=8/16 次，看基座自己能不能采出正确答案。
- **示例情形，尚未实测**：若 base pass@1 ≈ 0.21、pass@8 ≈ 0.35，而目标是 0.545，说明只提高已有正确答案的出现频率可能不够，应检查判卷器、奖励与额外信息的作用。有限次 pass@8 **不是 RL 最终准确率的数学上限**，不能由这一个数字断言 E2 必需或 RL-only 必败。
- 若 base pass@8 已经 0.6+，说明基座有时能答对较多题，值得实测训练能否让正确答案更常出现；它也不保证实验一定达成判据 P。

这个测量需要对同一批题多次采样，目的与学习清单【训练能否扩大答对范围】讨论的 `pass@k` 分析相同；论文在所测设置中的发现不能直接充当本项目的结论。M2 尚未运行，须等服务器可用。

### M3 — 奖励的「可被白拿程度」（已完成，结论直接影响奖励设计）

**[实测]** 完全不看图、永远输出同一个答案，在各奖励上能拿多少：

| 奖励 | 恒答策略 | 白拿分数 | 判断 |
|---|---|---|---|
| `wafer_format` | 任意含 7 个字段的固定 JSON | **1.0000** | **死奖励** |
| `wafer_radial` | 恒答 `center` | **0.8333** | **近乎死奖励** |
| `wafer_clock` | 恒答 `6` | 0.1155 | 有信号 |
| `wafer_class` | 恒答 `Edge_Loc` | 0.1190 | 有信号 |

**这就是旧 RL 网格「跑通但零增益」的机制解释**：四个奖励里两个几乎不含信息，另两个（class 0.9、clock 0.63）在 SFT 起点上已经不低，于是 30% 的步组内奖励完全相同、优势为 0、不产生梯度 **[记录]**。

**→ 结论：新计划的必要前提是重新设计奖励（第 3 节），而不是换算法或换学习率。**

## 3. 奖励重设计（本计划的主要工程量）

设计原则三条：**① 零标注可得；② 恒答拿不到高分；③ 在起点附近仍有组内方差**（否则 GRPO 拿不到优势）。

| 字段 | 现在 | 改成 | 为什么 |
|---|---|---|---|
| `radial_zone` | 与退化标签 `_zone(centroid_r)` 比对，恒答 0.8333 | 用 §6.7 已实现过的 **`mean_radius` 判据**，或直接改成**连续**量：与几何 `radial_density` 的余弦相似度 | 质心判据对对称图案恒为 center，是标签问题，不是模型问题 |
| `clock_direction` | 0/1，±1 扇区算对 | `1 − d/6`（d = 环形距离，0–6） | 0/1 在起点 0.63 上组内方差小；连续奖励在任何起点都有梯度 |
| `size_r` | **没有奖励** | `exp(−|Δ|/τ)`，τ = 0.25R | 现在完全没被奖励；而它恰恰是「真没学会」的字段（与真值相关 0.0382 **[记录]**） |
| `format` | 7 字段存在比例 | 保留，但**降权**到 0.1 以下 | 恒答满分，只该当门槛，不该当目标 |
| `defect_type` | 与可信标签比对 | **保留，但要显式区分两个版本**：① 零标注版（不启用）② k 标注版 | 这是唯一需要标注的奖励，也是标注预算曲线的自变量 |

**另外要修的两处**（都来自项目自己的记录）：

- `WaferRadial` / `WaferClock` 在「样本无几何 gold」时返回常数 1.0 **[记录源码]**。这等于给这部分样本白送满分、并且压掉组内方差。应改为**跳过该样本**（不计入这一项），而不是给 1.0。
- 奖励的组内方差要**逐 run 上报**（项目已有 `reward_signal` 机制 **[记录]**），任何一项 std ≈ 0 就应该在报告里被标成「不产生梯度」。

## 4. 实验分四段（每段一个可回答的问题 + 一个停止条件）

### E0 冻结与仪器化（0.5–1 天，不花 GPU）

1. **人工双审**：`benchmark/review/` 两张表填完并跑 `merge_review.py`。**这是全项目唯一的 BLOCKER**，不解决则所有分数永远是草稿分。
   （如果这一步暂时做不了，就在所有报告里带 `draft_pending_human_review` 限定语，但**不要**宣称基准已冻结。）
2. **噪声地板**：同一配置跑 3 个种子，得出本基准上的分数离散度。**已有素材**：`GRPO G=4 lr1e-5` 的三个抽样 = 0.6230 / 0.6071 / 0.6429，极差 0.0357 **[记录]**。新计划的任何效应必须与它比。
3. **冻结 run 集合**：把要跑的 run 列表写成文件并冻结，表格由磁盘枚举生成（复用 `tools/run_set.py`）。
4. **预注册**：把第 1.3 节的 P/Q/R/S 写进文件、写清判定规则，再开始跑。

### E1 — RL-only，**零标注**（回答 mentor 问题的字面版本）

- 起点：**基座**（不是 SFT adapter）。
- 数据：整个 train 划分（4721 张），提示词与结构化题一致。
- 奖励：`format`(0.1) + `radial`(0.4，修正后) + `clock`(0.4) + `size`(0.1)。**不含 `defect_type`。**
- 固定：150 步、G=4、accum 4（有效批次 16）、lr 1e-5、种子 3407、温度 1.0。
- 测：格式合规率、几何三字段、**以及分类准确率（副产物）**。
- **风险与对策**：基座可能根本不输出 JSON → 所有奖励 0 → 无梯度。对策是加一个**纯格式预热**（用程序合成的 JSON 骨架做几十步 SFT，不含任何教师内容和标签）。这一步要如实标注为「格式对齐，不是知识蒸馏」。
- **停止条件**：格式合规 > 0.9 但三个几何字段一个都不升 → 先查 verifier 与奖励实现，不要加大预算。

### E2 — 标注预算曲线（**这是主实验**）

- 只加一个自变量：`defect_type` 奖励启用的标注数量 k ∈ {0, 50, 200, 1000, 4721}。
- 其余全部与 E1 相同。**k=0 这一格就是 E1。**
- 产出：**「准确率 vs 标注数量」的一条曲线**，以及在同一批 252 行上的成对检验。
- 这条曲线的读法：如果 200 个标注就能到 0.55，那 mentor 的成本问题答案是「几百个标注就够」；如果 4721 个才追上 SFT，答案是「省不了多少」。

### E3 — 归因：教师标注的 prose 到底值多少分（**直接回答成本问题**）

在同一冻结基准上跑三个 SFT 变体，只改训练数据的内容：

| 变体 | 训练数据 | 回答的问题 |
|---|---|---|
| SFT-A | 只给类别标签（无教师 JSON、无教师描述） | 便宜的标签值多少分 |
| SFT-B | 标签 + 几何 gold 的结构化答案（**无教师散文**） | 数学金标能不能替代教师 |
| SFT-C | 现在的完整数据（含教师散文） | 教师散文的**增量**价值 |

**如果 SFT-B ≈ SFT-C，那整个教师蒸馏管线（1060 万 token、deepseek 额度耗尽、双模型交叉）就是可以砍掉的。** 这是本计划里最便宜、可能最有价值的一次实验。

### E4（可选）— 把几何 verifier 当成品

不训练，直接用几何分类器（200 标注版，0.6088；全标注版 0.6693）。它是**成本下界基线**，任何 RL/SFT 方案都必须超过它才值得做。

## 5. 反「乱」的机制（针对 mentor 的批评 + 项目自己 §8 的 20 条教训）

旧实验被说「乱」，具体的病因是可核对的，新计划逐条对症：

| 病因（旧） | 证据 | 新计划的对策 |
|---|---|---|
| 10 个 run 同时动 IS 层级、组大小、有效批次、学习率、种子 | `LIMITATIONS.md` §5.2 自记 | **一次只动一个变量**；标注预算是唯一自变量 |
| 有效批次跟着组大小平方变（16/64/1024） | §5.2 自记 | **accum 固定为 4**，不再跟 G 走 |
| 噪声地板最后才建立 | §5.2.7/5.2.8 | **E0 先立地板**，任何效应先与它比 |
| 表格由手写 run 清单重建 | §8 第 15 条 | run 集合冻结 + 由磁盘枚举（`run_set.py`） |
| 用边际 CI 重叠判显著性 | §5.2.2 | 用**成对 McNemar** |
| 奖励里两个是死的 | 本次 M3 [实测] | 奖励先审计再训练 |
| 失败被记成 WARNING / 完成标记写反 | §8 第 16、20 条 | 复用已修好的 `land_finish.sh` 与极性已校正的守卫 |

**另加两条新纪律：**
1. **每个 run 必须同时上报**：奖励四项的均值与组内 std、空转步占比、解析失败率、以及**verifier 与模型的一致率**（用来检测 reward hacking）。
2. **【实测】必须报的对照**：几何 verifier 自身的分数（0.6693 / 200 标注 0.6088）。任何 RL 结论旁边都要有这一行，否则会把 verifier 的分数误读成模型的分数。

## 6. 资源估算

- 一个 RL run：150 步、G=4 ≈ 2400 s ≈ 40 分钟 **[记录]**；G=32 约 2.7 小时 **[记录]**。
