# FabLAW：实验大纲与执行约束

版本：v1，2026-10-01。状态：**方案已列出，实验未启动，待用户审阅**。

这是本次会话的实验提案与 Agent 执行约束。用户已确定后续 GPU 实验使用学校服务器；本文件把 FabLAW 方向拆成可核对的步骤。具体训练规模、主要指标的判定阈值和总预算仍须在正式运行前锁定，不能假装已经确定或完成。

## 1. 我们到底要验证什么

用少量可靠的晶圆判读示例教会本地模型基本答题，再把“哪些事实要说对、哪些内容不能乱说”写成程序可核对的判据，是否能减少对大量教师描述的依赖，并提高缺陷判读能力？

给模型示范正确答案、让它照着学，叫**监督微调（SFT）**；让模型自己回答、按可核对的分数调整，叫**可验证奖励强化学习（RLVR）**；“判据体系（rubric）”就是这份分项打分清单。

必须分开回答三个问题：

1. 教师写的完整描述，比已有类别标签和程序算出的几何事实，多提供了多少价值？
2. 同样的少量冷启动示例下，奖励训练是否比继续监督训练更有效？
3. 改进判据是否带来独立评测上的增益，还是只是让模型更会迎合打分程序？

“接近或超过 Kimi”“判据质量比数据规模更重要”“可推广到其他模态”，目前都属于待检验主张。实验不以证实摘要为任务，也接受负结果。

## 2. 固定范围与工作地点

- 验证场景：公开晶圆 BIN 图的九类识别、形态/位置/尺寸描述，以及不存在内容和工艺根因的幻觉检查。
- 学生基座：`Qwen/Qwen3.5-9B`，推理输入为图片与问题，不提供类别答案、几何答案、教师输出或含答案的文件名。
- 训练框架：ms-swift。学校服务器环境重新核对，固定模型 revision、框架提交和依赖版本；不把旧服务器环境默认复制成事实。
- 教师参照：WorkBuddy 可调用的 `kimi-k3-1`。记录调用日期、目录/API 标识、提示词、解码设置、原始响应和用量；服务端模型版本不可固定时如实披露。
- GPT-6.1-sol ultra 可用于候选标注、检查和讨论；每次运行如实记录实际模型与推理设置，不称真人专家。
- 本机：清单、图片与标注准备、数学规则、小型测试、公开数据的 WorkBuddy 请求。
- 学校服务器：模型训练、GPU 推理、完整模型评测；实际占用哪些 GPU、存放在哪里，以当时核验和实验室规则为准。
- 公开数据上的外部模型对照，与真实产线数据只走获准本地环境，分层陈述。学校服务器不是厂内环境，不能用这轮公开数据实验冒称已经完成厂内部署。

本轮暂不开展 SEM、FDC、多轮问答、根因推断、图像检索训练、视觉编码器改造或算法网格搜索。这些不作为本轮验收必需项；历史产物继续保留。

## 3. 执行顺序与每一步的出口

### 阶段 A：先把实验合同和预算写清

要做：

- 核对本地数据、原始矩阵、完整教师产物和旧权重分别是否可得；不要假设旧服务器上的内容已在学校服务器。
- 区分训练集、改提示词/规则的开发集、最终确认集；写死主要指标、同一套问法、解析规则、失败计分和模型选择方式。
- 核对学校服务器当前 GPU、存储、隔离环境、使用规则与小测试速度。历史硬件记录不能代表当前可用资源。
- 在恢复积分测试后，用代表性公开晶圆及拟采用的标注提示，测实际调用用量、失败/重试和输出质量。积分容量按实际用量估算，并给审核、重标和直接推理对照预留预算。
- 只通过 JSON 格式检查的图片，不等于合格标注。单张普通识别测试或单张晶圆测试，也不能代表完整标注成本。

出口：一份版本化的实验配置与预算清单。明确少量冷启动集合规模 `k`、教师参照集合规模 `N`、主要比较、种子和总预算。`k`、`N` 在此处是待定参数，不是已测数据量。

不满足出口时：可以继续只读审计和本地规则测试，不做批量付费标注或正式训练。

### 阶段 B：整理数据与独立评测依据

要做：

- 检查稳定样本 ID、图像指纹、可信类别来源、渲染版本和批次（lot）；同一晶圆的所有变体在同一划分，训练/开发/测试批次互不交叉。
- 几何量能从原始矩阵得到的，优先使用原始矩阵；只有 PNG 时，明确估计方法与限制，不能把反推量冒称原始矩阵金标。
- 数学规则给出可核对的几何候选；模型生成候选描述；真人审核记录独立保存。来源不能混写。
- 旧 `benchmark/` 已被分析多次，且元数据仍标草稿；保留它作历史桥接。最终确认集应由未参与本轮规则、提示词和模型选择的数据组成。
- 需要真人确认的标签、形态边界及争议样本，交由真人处理。未完成时可做注明草稿的技术验证，不宣称专家金标或正式能力验收。

出口：带来源、划分、指纹、审核状态的数据清单和评测协议。新产物另建目录，旧快照不覆盖。

### 阶段 C：先做基础对照和教师描述价值实验

先保存未经本项目训练的基座回答；再建立几何分类器对照。几何分类器用图像计算出的特征猜类别，拟合时用到的标签必须计数，不能称零标签方案。规则直接答题与模型奖励判卷是两个不同角色。

沿用方案甲的 E3 问题，比较：

- **SFT-A：只给类别标签。**
- **SFT-B：类别标签加可核对的几何答案。**
- **SFT-C：完整 Kimi 教师标注。**

三者使用相同基座、同一组图片 ID、相同输入题面、可训练模块与预定数据呈现预算；改变的是训练答案包含什么。记录答案长度、训练 token、GPU 时间及筛选来源，不能假装所有计算量完全相同。

选择图片名单时不依据某一教师是否“接受”它。若受数据可得性限制必须沿用教师筛过的集合，就披露这项依赖，不宣称整个教师流程都已消除。旧教师 SFT 可作历史桥接，不替代本轮统一协议下的 SFT-C。

出口：明确教师描述的额外收益及成本；只在预定差距和同题配对的不确定范围支持时，才说两者足够接近。如果标签加几何已经有效，优先保留这条更简单的方案。

### 阶段 D：少量可靠示例与稳定冷启动

少量示例覆盖九类、典型与困难图案。按训练批次选样，不向模型泄漏原标签；保留原始候选、修改原因和最终来源。几何检查发现冲突时隔离，不凭模型自报置信度认定真值。

来源分两种：

- 真人实际标注/确认的集合，可以称专家标注或人工确认。
- GPT 或 Kimi 完成的集合，只能称模型辅助冷启动；不能据此证明专家知识迁移。后续真人确认也要记录确认范围和真实工作量。

先完成端到端小测试：图片确实进入模型，答案没有藏在问题里，只对回答部分训练，参数确实更新，附加权重与合并权重推理可核对。再做逐类小样本，最后运行冻结配置的冷启动 SFT。

出口：版本固定的冷启动模型，以及类别、事实字段、格式和错误分布的开发集记录。技术不稳定时先修接线，不靠强化学习掩盖问题。

### 阶段 E：写判据，先证明它能正确打分

判据至少区分：

- 必须说对：可信缺陷类别、适用的形态、径向位置、主要方向及尺寸定义。
- 不得乱说：图中不存在的结构、没有依据的工艺根因或伪精确数字。
- 不适用/不确定：整圈图案没有唯一钟点方向；缺金标、拟合失败、无主要缺陷等情况必须显式处理。

确定性可计算的量按锁定定义与容差核对；难以可靠编码的语义事实保留独立审核，不强行把某个几何分类器的类别输出当真值。

用正确、错误、空值、截断、固定答案和根因幻觉等例子检查规则；测在冷启动附近，同题多个回答是否能获得不同分数。记录错误扣分、错误放行和覆盖率。缺金标不能给满分，也不能静默删掉最终评测难例。

出口：固定规则版本及其独立开发集审计记录。规则明显判错或大量失去区分能力时，先修规则并回归验证，不直接扩大训练。

### 阶段 F：把 RL 和判据迭代的作用拆开

从阶段 D 的同一个冷启动检查点开始，比较：

- **F0：不再训练**，保留冷启动成绩。
- **F1：继续监督训练**，检验额外训练本身是否已经有用。
- **F2：固定判据奖励训练**，检验 RLVR 的额外作用。
- **F3：迭代判据奖励训练**，检验修判据的额外作用。

F1/F2/F3 固定训练图片池、输入、可训练模块、种子和主要数据呈现预算，另报各自实际计算及人力成本。不能同时声称“图片呈现次数完全一样”和“GPU 时间完全一样”，除非确实做到。

F3 的扣分归因、规则修订和回归只读训练/开发数据。预定修订轮数、候选选择规则和预算；F2 获得可比较的训练预算。修订次数及投入全部记账。最终确认集不参与逐例归因。

同分回答较多时，先诊断规则质量和采样；跳过缺少奖励差异的组（DAPO 的 Dynamic Sampling）只作为有证据后启用的候选改法，单独版本化，不自动换算法或扫描参数。

出口：四条路线的完整输出与成本，以及独立指标上的增量。所有正式关键比较使用预先固定的多个种子；先小测试测吞吐，再决定能承担的正式预算。

### 阶段 G：统一评测、归因与报告

最终在同一图片、同一主问法、同一解析和失败规则下，报告基座、几何分类器、SFT-A/B/C、F0–F3，以及 Kimi K3 直接推理。Kimi 的最终确认输出在题面锁定后生成，不能回流训练或规则修改。

必须检查：

- 各类同等权重的分类得分（Macro-F1）、准确率、逐类召回及混淆情况；不能只报总体最好数字。
- 形态、位置和尺寸的事实一致性；无依据内容、空回答、拒答、解析失败与截断。
- 几何分类器答对的 E 集、答错的 H 集，以及困难类别。子集由固定分类器划分，不按模型表现重新挑选。
- 原图与移除缺陷信息后的图、固定的备用问法。信息移除是诊断，不能把原标签冒称改图后的正确标签；旋转等合法扰动同步变换方向金标。
- 同题配对的成绩差及按批次抽样的不确定范围、各训练种子的全部结果；旧运行的种子极差不作为通用显著性门槛。
- 标注条数、可信标签使用量、积分/token、审核与规则工时、GPU 时间和推理成本。规则编写不记为免费，公开已有标签不记为无监督。

评测不能只复用训练奖励分数来证明能力。测试类别依据、事实判定与必要的真人盲审独立于奖励优化；相同规则的合规分只能说明规则合规。

出口：每个研究问题得到支持、不支持或尚不能判断的结论。没有运行的任务标 `not run`，没有完成的审核保留草稿状态；不事后换指标、问法、分母或挑最佳种子。

## 4. 本轮允许声称到哪里

- F2 相对 F0 有增益，还不足以证明 RL 比继续 SFT 更好；必须看 F1。
- F3 相对 F2 的差异需结合额外规则、人力、数据和计算成本解释。
- H 集上涨是有用诊断，不是看图能力的充分证明；还须结合信息移除与泄漏检查。
- SFT-B 接近 SFT-C，只支持本设置下教师描述增量有限；没有自动证明所有教师筛选和知识都可取消。
- 未拒绝“二者相等”不能证明接近。正式运行前定义可接受的性能差距，区间足够窄且落在预定边界内，才讨论接近。
- 想声称“判据质量比数据规模更重要”，必须另做明确的数据规模与规则质量对照，不能从 F3 单条增益外推。这是阶段 F/G 之后的条件性扩展，不自动新增运行。
- 本次公开数据验证不等于产线部署验收，更不证明 SEM/FDC/根因推断的推广性。

## 5. Agent 不跑偏的具体机制

每次开工先给出：**当前阶段、这一步的问题、计划产物、前置条件、预算或是否消耗付费/ GPU 资源**。一次只推进有依赖依据的步骤。

每个正式运行必须保存：实验 ID、起点、主要变量、数据 ID 与指纹、代码提交、版本、题面、规则版本、种子、配置、最大预算、检查点选择、停止条件、原始输出和失败记录。比较关系不写清，不启动。

发现技术错误先诊断修复；发现判据或结论问题先报告用户。是否写入 `踩雷记录.md` 仍按用户原要求确认，不能以本大纲为理由自行改写它。

更换研究问题、基座、主要指标、评测数据边界、扩大总预算或增加范围外任务，必须先记录变更理由并取得用户明确指令。例行实现、测试和修复不逐步索要确认。

`code/`、`docs/`、`results/`、`benchmark/` 保持历史快照。新工作另存、来源可追溯；项目公开，连接端点、账号、凭据、公司/客户信息不进入本仓库。

当前已完成大纲与约束文档；用户随后明确恢复了代表性晶圆的积分测试。允许执行这项小规模成本校准，不自动扩展为正式批量标注、数据上传或训练。
