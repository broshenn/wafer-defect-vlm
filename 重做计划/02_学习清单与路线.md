## 核实结果（2026-09-28，助教联网核过）

原清单里凡是带 ⚠️ 的编号，都是助教凭记忆写的。**下面这三篇已核实**，编号和结论都可靠。

### A3 —— 本清单最重要的一篇，已核实

**《Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?》**
Yue et al.（清华 LeapLab / 上海交大），**arXiv 2504.13837**，ICML 2025 + **NeurIPS 2025 Oral**。
项目页 `limit-of-RLVR.github.io`，代码 `github.com/LeapLabTHU/limit-of-RLVR`。

**取什么**（四条，按对我们重要性排）：

1. **`pass@k` 在大 k 上反转** —— RL 训完的模型在小 k（如 k=1）上更好，
   但**大 k 上基座追平甚至反超**。跨模型族（Qwen/LLaMA/Mistral）、跨规模（7B–72B）、
   跨算法（PPO/GRPO/RLOO/Reinforce++）、跨领域（数学/代码/视觉推理）一致成立。
2. **RL 提高的是"采样效率"，不是"能力边界"** —— 它把输出分布**偏向被奖励的路径**，
   采样到正确答案更省事；但**边界没有扩大，甚至随训练收窄**。
3. **RL 采出来的路径，本来就在基座分布里** —— 覆盖率与困惑度分析证明这一点。
4. **「蒸馏能扩边界，RLVR 不能」** —— 从教师（如 DeepSeek-R1）蒸馏**确实引入新的推理模式、扩大能力边界**。
   ⇒ **这一条直接支撑我们的 E3（教师散文值多少分），也直接决定 mentor 那个问题的上限。**

**对我们的意义**：**M2（base pass@k）就是照它做的。** 如果基座的 pass@8 只有 0.35，
那 RL-only 到 0.545 就**理论上不可达**——因为 RL 只能把已有答案采得更勤，不能造出没有的答案。

**同行评审里记的限制**：实验都在 7–32B 的较小模型上做的；相关工作报告长时间、熵稳定的 RL（ProRL）
能扩边界，说明"能否扩"可能取决于训练范式。

### A4 —— 防自欺的那一篇，已核实

**《Spurious Rewards: Rethinking Training Signals in RLVR》**，Shao et al.，**arXiv 2506.10947**。

**取什么**：

- **随机奖励也能涨分**：Qwen2.5-Math-7B 用**随机奖励**在 MATH-500 上涨 **21.4 个百分点**，
  对比**真值奖励**的 29.1 个百分点。其他"假奖励"：格式奖励 +13.8%、错误标签 +24.1%、
  1-shot RL +26.0%、多数投票 +27.1%。
- **机制**：GRPO 的 **clip 项有偏置**，会**放大预训练期学到的高先验行为**。
  在 Qwen2.5-Math 上，被放大的行为是"用代码推理"——频率从 65% 升到 90% 以上。
- **强模型依赖**：这些行为高度依赖具体模型族；同样的假奖励对 **Llama3 / OLMo2 无效**。
- **作者的建议**：**把"假奖励"对照纳入常规诊断**，并在多个模型族上验证，
  否则在单一模型族（Qwen）上的涨分可能只是**放大了它已有的行为**。

**对我们的意义**：**我们必须加一个"假奖励"对照格**，否则"RL 涨了"可能只是格式或先验被放大。
另外它的机制解释也印证了我们的空转步问题（clip 项 + 零方差组）。

### B3 —— 我们已经踩到的坑，它有现成解法，已核实

**《DAPO: An Open-Source LLM Reinforcement Learning System at Scale》**，ByteDance Seed + 清华 AIR，
**arXiv 2503.14476**。

**取什么**：**Dynamic Sampling（动态采样）** ——

> **把"全对"和"全错"的 prompt 丢掉**，只保留组内有区分度的样本，直到凑满一个 batch。

**它要解决的问题，和我们的一模一样**：

> 一个 prompt 下所有输出都对（或都错），奖励相同 → **组内优势为 0** → **策略梯度为 0** →
> 这一批的梯度变小、对噪声更敏感 → 样本效率下降。

**对我们的意义**：**这就是我们那 36% 空转步的现成解法**，而且比"改奖励"更直接。
DAPO 另外三招也值得看：Clip-Higher、Token-Level Policy Loss、Overlong Reward Shaping。
消融表：Naive GRPO 30 分 → 逐步加技术 → **DAPO 50 分**（AIME24），且只用一半训练步数。

## 第 0 部分：读论文之前，先建立六个概念

这六个概念是这次重做计划的全部智力抓手。每一个我都用**你自己项目里的数据**讲一遍，读完这一段你再去看论文，会知道该找什么。

### 概念 1：verifier 的天花板（verifier ceiling）

**定义**：当奖励由一个自动判据（verifier）给出时，模型在这个任务上的上限**不会超过 verifier 与真值的一致率**。

**你项目里的例子**：`radial_zone` 的奖励是「与几何 gold 一致」。而几何 gold 恒答 `center` 就有 **0.8333** 的命中率（我今天实测）。所以这个奖励的 verifier 上限是 0.83，而且**它是退化的** —— RL 只要学会「永远答 center」就能拿到 0.83 分。旧实验里 `WaferRadial` 的实际均值是 **0.865**，与这个「白拿分」几乎一样。

**推论**：在设计任何 RLVR 实验之前，先量 verifier 自己的准确率。**这是本计划 M1/M3 的全部理由。**

### 概念 2：pass@k 与「锐化 vs 发现」

**定义**：从一个模型采样 k 次，只要有一次对就算对，得到 pass@k。pass@1 与 pass@k 的差距 = 模型「会但采不出来」的那部分能力。

**为什么它决定了我们实验的形态**：如果基座 pass@1 = 0.21 而 pass@8 = 0.35，那么 RL 能做的多半是**把这 0.35 里的正确答案变得更可能被采到**（锐化），而不是把 0.35 提到 0.55（发现）。要到 0.55，就必须有**外部信息进来** —— 而在这里，外部信息就是「k 个标注」或「更强的几何 verifier」。

**推论**：M2（测 base pass@k）是判断「E2 标注预算曲线是不是必需」的唯一依据。**先测它，再决定跑几个 run。**

### 概念 3：0/1 奖励在 GRPO 里会死

**定义**：GRPO 的梯度来自**组内**优势：同一个 prompt 采 G 个答案，优势 = (自己的分 − 组内均值) / 组内标准差。如果一组里所有答案得分完全相同，优势全为 0，这一步不产生任何梯度。

**你项目里的证据**：旧实验的 10 个 run 里，**7.33%–42.00% 的步组内奖励完全相同**（均值约 30%），这些步完全空转 **[记录]**。机制是：`format` 奖励恒答就满分（组内方差 0.0005），`radial` 恒答 0.83，两者都压不出方差。

**推论**：奖励要设计成**在起点附近仍有组内方差**。这就是为什么新计划把 `clock` 改成 `1 − d/6` 的连续奖励、给 `size_r` 加连续奖励、并把 `format` 降权。相关论文见 B4（DAPO 的 dynamic sampling 正是为了解决同一件事）。

### 概念 4：reward hacking / 古德哈特定律

**定义**：当一个指标变成目标，它就不再是好的指标。策略会去攻击 verifier 的漏洞，而不是学到你想让它学的东西。

**你项目里已经踩过的一半**：`predictDefectType` 来源不明（`AGENTS.md` §5.1 明确不许把它当真值）；双教师仲裁用几何第三方裁决 —— 而几何本身就有 0.24 的类召回（Loc）。**用一个有错的 verifier 去训练，模型会学到 verifier 的错，而且会放大。**

**推论**：新计划必须包含「reward hacking 检测」：训练过程中定期用**独立于奖励的指标**（冻结基准上的分类准确率、被测类召回）监控，并检查模型是否学会了恒答退化值。

### 概念 5：RLVR 的适用范围（能验证什么，就只能得到什么）

**定义**：RLVR = Reinforcement Learning with Verifiable Rewards。它要求奖励能被**确定性、自动地**算出来。所以它天然只能覆盖任务里「可判定」的那部分。

**你项目里的三档**：

| 档 | 字段 | 零标注可验证？ |
|---|---|---|
| A | 格式合规、几何字段（径向/钟点/尺寸/覆盖率） | ✅ 完全可验证（几何由图片确定性算出） |
| B | 类别（9 类） | ⚠️ **不能**由图片自证，需要标注、或一个弱 verifier（而弱 verifier 有 0.24–0.32 的类召回） |
| C | 描述（caption）的质量、根因 | ❌ 没有 verifier；用 LLM 当裁判 = 又变成蒸馏，且会漂移 |

**推论**：mentor 的目标只在 A + B 上能被评测。**caption 与根因不在 RLVR 的可达范围内**，报告里必须这么写，否则「RL 追平 SFT」会被读成「所有指标都追平」。

### 概念 6：SFT 装进模型的是什么，RL 装进去的又是什么

**SFT** 装的是「分布」：什么输入该配什么输出，包括风格、语言、格式、以及教师的判断。**RL** 装的是「偏好」：在同一个 prompt 的多个采样之间，抬高哪些、压低哪些。

**你项目里的证据**：SFT 把准确率从 0.2143 抬到 0.6230（+0.41）**[记录]**；而 RL 在 SFT 之上跑了 10 个 run、每种配置都没能显著超过它 **[记录]**。但 RL 确实改变了机制层面（空转步从 36.00% 降到 15.33%，单变量 IS 对照下降 6.0 个百分点）——**机制动了，分数没动**。

**推论**：mentor 的问题本质上是「能不能用 RL 装进 SFT 装的**那部分**」。而 SFT 装的一部分是教师的知识（不可验证），一部分是格式与几何（可验证）。**新计划就是把这两部分分开量。**

## 第一部分：核心问题 —— RL 能不能不要 SFT、不要标注

> 读完这一组，你要能回答：**「RL 从基座直接开始」在什么条件下成功、在什么条件下只是幻觉。**

- **A1｜DeepSeek-R1（DeepSeek-AI, 2025, arXiv 2501.12948）**
  - 取什么：**R1-Zero** 那一节的实验设计 —— 从**基座**直接 RL、不做 SFT，以及它**为什么要额外补 SFT**（可读性差、语言混杂）。
  - 它对我们意味着：mentor 的想法有先例；但先例里 R1-Zero 的奖励是**数学题答案**（严格可验证、覆盖率高），而我们的类别奖励**不可自证**。差别就在这里。

- **A2｜SimpleRL-Zoo / 「Reinforcing LLMs to Reason without Supervised Fine-tuning」（Zeng et al., 2025）⚠️**
  - 取什么：**哪些基座做得到、哪些做不到**，以及他们强调的「基座选择比算法重要」。
  - 对我们：如果 9B 基座在晶圆图上 pass@8 都很低，那么 A1 的路线在我们这里可能直接不成立 —— 这就是 M2 要测的。

- **A3｜「Does Reinforcement Learning Really Incentivize Reasoning Capacity Beyond the Base Model?」（Yue et al., 2025）⚠️**
  - **这是本清单里最重要的一篇。** 取什么：他们的 **pass@k 分析**。结论大意是：RL 后的模型在 pass@1 上更好，但在较大的 k 上**反而不如基座** —— 即 RL 是**锐化**分布，不是扩展能力边界。
  - 对我们：**它给了我们一个「不跑 RL 就能估出上界」的方法。** 直接照着它做 M2，然后用 base pass@k 预估 RL-only 的天花板。如果上界 < 0.545，那就应该先改 verifier 或加标注，而不是加训练步数。

- **A4｜「Spurious Rewards: Rethinking Training Signals in RLVR」（2025）⚠️**
  - 取什么：他们发现**随机奖励**在 Qwen 数学上也能涨分。也就是说「涨分」本身不足以证明 RL 学到了东西。
  - 对我们：**这是防自欺的一篇。** 我们的实验必须包含「用随机 verifier」或「用恒答基线」的对照格，否则 0.21 → 0.55 这个变化可能只是格式对齐的副产品。

- **A5｜「The Invisible Leash: Why RLVR May Not Escape Its Origin」（2025）⚠️**
  - 取什么：RLVR 的解空间被基座分布「拴住」的论证。
  - 对我们：给「RL-only 的天花板 = 基座分布 + verifier 信息量」这个直觉一个理论支撑，也是写 limitation 的好材料。

## 第四部分：标注经济学 —— mentor 真正关心的那一侧

> 读完这一组，你要能回答：**「多少个标注就够？什么时候该标注、什么时候不该。」**

- **D1｜主动学习（Active Learning）综述与晶圆/半导体缺陷检测里的应用 ⚠️**
  - 取什么：不确定度采样 / 多样性采样在缺陷分类上的增益曲线。
  - 对我们：**E2 的曲线就是主动学习曲线的一条基线**；如果不做主动学习，随机抽 k 个是最弱的对照，但也是诚实的起点。
- **D2｜半监督 / 自训练（pseudo-labeling, FixMatch 一类）⚠️**
  - 取什么：伪标签的自确认偏差。
  - 对我们：`predictDefectType` 那个悬案就是伪标签问题；AGENTS.md §5.1 的谨慎是对的，读它你会知道为什么。
- **D3｜少样本/零样本缺陷分类的近期工作（半导体检测方向）⚠️**
  - 取什么：别人在 WM811K 上的**便宜方法**能到多少分。
  - 对我们：**这一项必须补** —— 我今天已经实测：一个 31 维几何 + 最近质心就有 0.6693。如果文献里有更便宜的方法到 0.75，那我们的 VLM 路线需要重新论证。
- **D4｜知识蒸馏 vs RL 的对比（Distillation vs RL for capability transfer）⚠️**
  - 取什么：什么情况下蒸馏优于 RL、什么情况下 RL 才能突破教师。
  - 对我们：E3 的理论背景。

## 第五部分：方法论 —— 怎么不再把实验做「乱」

> 读完这一组，你要能回答：**「为什么我上一轮 10 个 run 得不出结论，下一轮怎么保证能。」**

- **E1｜Colas et al.《A Hitchhiker's Guide to Statistical Comparisons of Reinforcement Learning Algorithms》（2018）⚠️**
  - **这一篇专门治 mentor 说的「乱」。** 取什么：为什么均值±标准差不够、什么是分层 bootstrap、什么是 IQM、怎么做「聚合度量」。
  - 对我们：新计划里每一张表都该按它的建议设计（我们现在只有 McNemar，够用但不完整）。
- **E2｜《Deep Reinforcement Learning that Matters》（Henderson et al., 2017）**
  - 取什么：种子、超参、评价协议对结论的影响有多大。
  - 对我们：**我们已经付过学费了** —— 三个种子的极差是 0.0357，而 lr 效应是 0.0556 **[记录]**。读它能把学费变成知识。
- **E3｜机器学习里的预注册（pre-registration）与「分析前先写判据」⚠️**
  - 取什么：怎么在跑之前把判据写死。
  - 对我们：`01_实验策略_v2.md` §1.3 的 P/Q/R/S 就是这个动作，缺一个引用。
- **E4｜你自己项目里的 `docs/LIMITATIONS.md` §8（20 条）—— 当成教材读，不是当历史读**
  - 它不是论文，但它比任何一篇论文都更贴近你要解决的问题：**怎么发现「看起来正常的结果其实错了」**。
  - 建议读法：每条只问两个问题 ——「这个失败会伪装成什么样？」「我这次的实验里有没有同样的形状？」。
  - 配套读 `AGENTS.md` §16 的三分法（能核对的事实 / 解释 / 未证实）。**这是你做实验报告的主干。**

## 第六部分：工程（决定你能跑几个 run）

- **F1｜ms-swift 的 RLHF 文档**（我们用的框架，已固定 commit `9d3d03d`）：`--importance_sampling_level`、`--num_generations`、`--gradient_accumulation_steps` 的确切语义。**旧实验的 `grad_accum` 写死 bug 就是没读文档导致的。**

## 第七部分：领域（把「晶圆」这件事本身学扎实）

- **G1｜WM811K（Wu, Jiang, Chen, 2015）** —— 9 类的定义与来源。**重点看 `none` 是什么**（它是垃圾桶类，不是「无缺陷」，占原始数据 85%）。

## 第八部分：降级（这几样不再是主线，别再把时间花在上面）

- GSPO vs GRPO 的**算法之争** → 已结论：在本设计里是**学习率**起作用，算法分不开。作为背景保留即可。
- 组大小扫描（G=4/8/32）→ 已在三档上都不显著，且有效批次与组大小绑死。**不再扫。**
- 学习率扫描（1e-5 vs 5e-5）→ 结论已成立（高学习率显著更差）。**新计划固定 lr 1e-5。**
- 视觉侧适配（`lora_llm`）→ 仍是一个**未测量**的选项，但在新计划里排在 E3 之后：先证明「语言侧 + 几何 verifier」不够，再动视觉侧。

**每周一次的动作**（建议）：

1. 读一篇（A/B/C/D/E 各挑一篇，按上面的优先级）。
2. 写三行进 `学习记录/`（能核对的事实 / 解释 / 未证实）。
3. 做一个小实验验证它（大部分不需要 GPU：M1 的规则版 verifier、奖励审计表、几何 verifier 的新阈值，本机都能算）。
4. 把结论折算成一句「所以我们的实验要改哪里」。

**自测题**（答不上来就回去补）：

1. 我们的四个奖励里，哪两个可以被「永远输出同一个答案」白拿？分别白拿多少分？
2. 为什么 `format` 奖励虽然满分率 1.0，却对 GRPO 几乎没有贡献？
3. 基座的 pass@8 是 0.35，RL-only 想达到 0.545，缺的那 0.195 必须来自哪里？
4. 一个几何分类器单独就有 0.6693，那么「RL 到 0.55」这个成功说明了什么、没说明什么？
5. caption 的质量为什么不在 RLVR 的可达范围内？如果要让它可达，需要什么代价？
6. 三个种子的极差 0.0357 与 lr 效应 0.0556 是什么关系？为什么这个数字决定你下一轮要跑几个 run？
7. 旧实验为什么「乱」？用 `LIMITATIONS.md` §5.2 的原文说清「有效批次 = 组大小²」这个混淆，以及新计划怎么避免它。

## 最后一条纪律

**这份清单不是让你读完再动手。** 顺序是：

1. **先做 M2（base pass@k）与 M1 的零标注规则版** —— 这两个测量本机或一次短推理就能完成，而它们可能会直接告诉你答案。
2. 同时读书单第一组的 **A3**（pass@k 那篇）。
3. 然后再决定 E1/E2 要不要跑、跑几个 k 值。

**如果 M2 显示 base pass@8 < 0.35，而 M1 的零标注 verifier < 0.45，那么 mentor 的「70 分」在当前信息量下不可达 —— 这种情况下最该做的是先改 verifier 或先要 200 个标注，而不是加训练。** 把这句话写进给 mentor 的一页纸里，比任何漂亮的训练曲线都值钱。
