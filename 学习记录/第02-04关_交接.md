## 一、第 2 关 · 切出考卷（`benchmark.py`）

### 1.1 出卷：`build()` —— 一次做两件事

- **要解决的问题**：从 test 的 589 张挑 252 条做成固定考卷
- **核心代码**：`code/projects/wafer-defect-vlm/src/wafer_vlm/benchmark.py:125-231`（`build()`）
- **8 个块**：① 保护现场（`:126-131`，非空目录默认报错，重建须 `--overwrite`）② 挑 252（`:133-134`）③ 写 `core.jsonl`（`:135-148`）④ 三张内容卷（`:149-163`）⑤ 题面（`:164-190`）⑥ 鲁棒性（`:191-196`）⑦ 检索（`:198-220`）⑧ `metadata.json`（`:222-231`）
- **结论**：**先定一个"根"（`core.jsonl`），后面 6 块全部从它派生，不再回头挑第二遍** —— 这是 `core.jsonl` 存在的唯一理由（避免"挑 7 次挑出 7 个不一样的结果"）

### 1.2 `core.jsonl` = 第 1 关清单的 252 行 + 5 个补的字段

- **实测**：与 `data/manifest.jsonl` 逐字段比对，**252/252 完全一致，一字没改**（`**row` 整条搬过来）
- **补的 5 个字段，分三类**（这一分类是讲清"为什么"的关键）：

| 字段 | 怎么来的 | 252 条里的值 |
|---|---|---|
| `difficulty_score` | **算的**（`:138` 调 `difficulty()`） | 0.0~6.0，共 18 种 |
| `gold_source` | **写死的常量** | 252 条全是同一句 |
| `annotator_count` | **写死的 0** | 全是 `0` |
| `agreement` | **写死的字符串** | 全是 `"pending_human_review"` |
| `caption_rubric` | **查表 + 抄特征**（`:141-146`） | 按类别分 9 组 |

- **为什么"写死的"要单独列一类**：它们是**声明**不是**结果**（252 条完全相同）—— 学生第一次答成"都是算的"，必须纠正

### 1.3 难度分：`difficulty()` —— 8 行，5 条规则

- **核心代码**：`benchmark.py:32-48`
- **5 条规则**：① `status != "ok"` +3 ② `defect_count < 10` +2 ③ `min(噪点,5)/5` +0~1 ④ 质心骑线（离 0.35 或 0.72 差 ≤0.05）+2 ⑤ `resultant_length` 在 0.18~0.32 +1 ⑥ 类别属于 4 个天生易混类 +0.5
- **`0.35` / `0.72` 不是随手挑的** —— 正是 `_zone()` 切"中心/中间/边缘"的两条线（`utils.py:137-142`）
- **怎么用它挑**（`balanced_core()`，`:51-66`）：**按类别分组 → 组内排序 → 前 70% 取"典型" + 后 30% 取"最难"**
- **实测对上**：`Center 90→30`（最容易 20 + 最难 10）、`Near_full 16→16`（10+6）、`none 26→26`（17+9）
- **「30」是上限不是配额**：库里 90 张也只取 30；库里只有 16 张就 16 张全拿；**不能去 train 里补**（那就是把考题发下去）

### 1.4 五张卷子怎么派生（`build()` 的后半段）

```
252 张 × 3 种问法 = 756    → inference_requests.jsonl
252 张 × 3 个扰动 = 756    → robustness_inference_requests.jsonl

```

- ① 分类（`:149-151`）② 结构化（`:152-160`）③ 描述（`:161-163`）—— **三张都是"从 core 抄字段"**
- ④ 鲁棒性（`:100-122` `make_robustness()`）—— **唯一要 `Image.open()` 读图、再写新图的一块**，多产出 756 张 PNG
- ⑤ 检索（`:198-220`）

### 1.5 检索卷的三个细节

- **query 每类 10 条**（`:199-202`），**用的是 `seed + 1`**（3408，选 core 用 3407）→ 让"选 query"和"选考卷"不相关
- **`graded_relevance()` 给每一对打 0/1/2**（`:75-82`）：类别不同 = 0；类别同且 `radial_zone` 同且钟点差 ≤1 格 = 2；否则 1
- **`clock_close()`**（`:69-72`）：`min((a-b)%12, (b-a)%12) <= 1` —— **12 点与 1 点只差 1 格**（直接相减会算成 11）
- **排除同批次**（`:214`）：`candidate["lot_name"] == query["lot_name"]` 跳过 —— 和第 1 关按批次切分**同一个理由**
- **实测**：90 query × 252 gallery = 22680，排除 175 → **qrels 22505 行**；每个 query 的候选 242~251；相关性分布 `{0: 20142, 1: 1925, 2: 438}`；**平均每个 query 只有 4.9 个"很像"的、21.4 个"同类但不像"的**

### 1.6 封卷：`freeze()` —— 不改内容，只盖章

- **命令**：`benchmark freeze --output ...`（**另一条命令**，不是 `build` 自动带的）
- **核心代码**：`benchmark.py:234-262`
- **三步**：① 数"几条没审"（`:236-237`，读 `annotator_count < 2 or agreement != "approved"`）② **默认报错**，要绕过必须显式 `--allow-pending`（`:238-239`）③ 记下两种结局 + 给每个文件按指纹（`:247-261`）
- **两种结局分开记（`:240-254`）**：全审过 → `status: "frozen"`；绕过 → `status: "draft_pending_human_review"` + `review_gate: "bypassed_by_allow_pending (252 samples unapproved)"`
- **为什么这么改**：最早的写法是 `"frozen_with_pending_review_OVERRIDE"` —— **含 `frozen` 一词会被断章取义**；改法是**把"能不能自称冻结"和"实际发生了什么"拆成两个字段**
- **实测**：`SHA256SUMS` **773 行**（其中 **756 个是 `robustness_images/` 的图，本机没有**）
- **后来真的核对过**：`final_acceptance.py:124-147` 重算所有指纹 → `results/reports/acceptance.json` 的 `benchmark.files_checked = 773, mismatches = [], passed = true`

### 2.1 先挑清单：`tools/filter_split.py`

- **要解决的问题**：**老师不能看考卷** → 必须先把 test 剔掉

### 2.2 老师怎么生成答案：`annotate.py`（195 行）

- **四个动作**：① 把 21 个数学特征拍平成文字（`:94`）② 发请求（`:100-115`：`system` 身份卡 + `image_url`（图片转 base64）+ `text` 题目）③ 从回答里抠 JSON（`:118` `extract_json_object()`）④ **存下一切**（`:120-132`：`model` / `prompt_version` / `usage` / `attempt` / `latency`）
- **失败也记、不中断**（`:133-144`）：老师 A 的 108 条失败就是这样留下的（`status: "error"`）
- **断点续传**（`:51-63` + `:70-71`）：`existing_ids()` 先读已成功的 → **换模型不用重跑**（这是 flash→v3.2 能接着跑的原因）
- **并发 12**（`:85-86`、`:146-163`）、`temperature=0.0`
- **实测 token**：老师 A 4,723,053 / 老师 B 6,696,238 / **合计 11,419,291**（`results/reports/teacher_token_stats.json`）

### 2.3 老师的核心提示词（`prompts.py`）

- **7 条提示词只有 2 条被调用**：`STRUCTURED_TEACHER_SYSTEM`（`:44`）+ `make_structured_teacher_prompt`（`:47-66`）
- **没被调用的 5 条**：`CAPTION_SYSTEM_PROMPT` / `CAPTION_USER_PROMPT` / `JUDGE_SYSTEM_PROMPT` / `make_judge_prompt` / `TRANSLATE_SYSTEM_PROMPT`
- **⚠️ 其中 `CAPTION_USER_PROMPT`（`:18-25`）是个精心写的描述模板**（含句式与示例），**但实际生成描述用的是 JSON 里那一句 `"caption_zh": "一个紧凑的中文客观描述"`**
- **系统卡原文里有一句关键的话**：「你必须结合图像和给出的**确定性几何统计**」
- **老师要填 10 个格子**：`defect_type` / `shape` / `radial_zone` / `clock_direction` / `density` / `continuity` / `size_r` / `caption_zh` / `caption_en` / `uncertain`
- **`prompt_version` 逐行记录 = `structured_teacher_v1`**（5423 行全是）—— 这是"实际用的是哪条提示词"的唯一硬证据

### 2.4 ⚠️ 可视性矩阵（面试陷阱，必讲）

| | 图片 | **数学特征** | **真值标签** |
|---|---|---|---|
| **老师**（写答案） | ✅ | ✅ **给了** | ✅ **给了**（`--include-label`） |
| **学生**（训练） | ✅ | ❌ | ❌ |
| **考试** | ✅ | ❌ | ❌ |

- **一句话**：**老师可以看尺子，学生不能看**
- **为什么**：学生若能看到特征，会学会"抄数字"而不是"看图"；考试只给图 → 能力崩塌，而训练分数看起来完美
- **宪章原文**（`AGENTS.md:172`）：*"教师生成时可以同时输入图片和由图片确定性计算出的数学特征，以减少方位、尺寸和环形判断错误；学生训练时只输入图片和问题。"*

### 2.5 老师是**三个模型**，不是两个

| 角色 | 文件 | 模型 | 条数 |
|---|---|---|---|
| 主标注 | `teacher_v1/primary_deepseek.jsonl`（5423 行 = 5315 成功 + 108 失败） | `deepseek-v4.1-flash` | 1532 |

- **换模型没重跑**：靠断点续传接着写；**逐行记了 `model`，没有把两个模型混记为一个**

### 2.6 两轮探针 —— 区分"能力验证"和"额度验证"（B11 的由来）

- **第一轮 · 能力验证**（`/tmp/probe_teacher.py`）：造合成图（绿圆 + 红弧在**顶部 = 12 点钟**），问 `{defect_type, radial_zone, clock_direction, size_r}` —— **要它说出图上特征**。结果 `deepseek-v4.1-flash` 答 **`clock_direction: 12` ✅**；**只覆盖 flash 与 qwen397b**
- **第二轮 · 额度验证**（`/tmp/quota.py`）：**同样造了图**，但问的是 `"Reply with JSON only: {\"ok\": true}"` —— **与图内容无关**，只看 HTTP 状态码。13 个模型挨个试，结论是 v3.2 "works"（**可用**，不是"能看图"）
- **顺带发现**：两个老师默认开着推理模式，`deepseek-v4.1-flash` 把 512 token 全烧在思考上、返回**空字符串** → 关掉 `enable_thinking` 后 36 token 出干净 JSON，**成本降约 20 倍**（实测 `image_tokens: 184`）

### 2.7 qwen 的复核名单是怎么定的：`curate plan`（`curate.py:146-169`）

```python
needs_qwen = (not check["passed"]          # ① deepseek 的答案没及格
              or is_boundary(record)        # ② 图被判为"边界样本"
              or stable_audit(..., 0.15))   # ③ 随机抽中 15%
```

- **实测触发**：`passed 5235`（98.5% 及格）· `boundary 5164`（**97.2%**）· `needs_qwen 5189`
- **设计意图约 30%，实际 98%** —— 日志原话：*"the audit plan selected 5189/5315 (98%) — far more than the designed ~30%"*
- **爆掉的原因**：`is_boundary()` 里 `filtered_points_removed > 0`（`:135`）—— **"只要删过哪怕一个噪点就算边界"**（= `踩雷记录` **A14**）
- **顺带看到的 deepseek 问题分布**：`radial_mismatch 2323` / `shape_suspicious 973` / `type_mismatch 78` / `root_cause_hallucination 31` / …
  - **⚠️ 那 2323 条要小心**：`validate()` 判位置用的是 `features["radial_zone"]`（`:78`）—— **就是那个用质心判位置的字段**，所以这 2323 条里可能藏着"老师看对了、标准答案错了"的冤案

### 2.8 裁决怎么做（`curate.py:172-229`）

- **第一步**：`core_disagreement()` 只比 **4 个字段**：`defect_type` / `shape` / `radial_zone` / `clock_direction`（钟点差 >1 格才算吵）
- **第二步**：`geometry_verdict()` **逐字段**判（`:183-214`）—— **第三方是什么，逐字段不同**：

| 字段 | 拿什么判 | 算数学吗 |
|---|---|---|
| `defect_type` | 跟**真值标签**比 | ❌ 已知答案 |
| `radial_zone` | 跟 `features.radial_zone` 比 | ✅ 数学（但字段本身有毛病） |
| `shape` | 查**人工写死的表** `SHAPES_BY_LABEL`（`:24-34`） | ❌ **人写的表** |
| `clock_direction` | 环形距离 ≤1 格 | ✅ 数学 |

  **→ "数学裁决"这个说法不准确**：4 个里只有 2 个是纯数学
- **第三步**：`arbitrate()` **要求所有争议字段都站在同一方才算赢**（`:223-228` 的 `all(...)`）→ 各赢一部分就返回 `None`（**隔离**）
  - 注释原文：*"它从不咨询任何一个老师，所以不会偏向那个恰好被叫做 primary 的一方"*；*"各赢一部分时返回 None —— 这是面对真实分歧时诚实的答案"*
- **三个特例**：`none` 类的位置必须答 `none`（`:195-196`）；`Near_full` 接受 `full` 或它自己的 zone（`:198-199`）；`expected_clock` 在 `resultant_length < 0.25`（朝向太散）时返回 `None`（`:50-54`）
- **实测**：1787 条吵架 = 判 deepseek **696** + 判 qwen **652** + 判不了 **439**

### 3.2 ⚠️ 一个盲区（**学生顺着"应该让强模型写数据"的直觉问出来的**）

- 而被比过的只有 4 个字段 → **`density` / `continuity` / `caption_zh` / `caption_en` 从头到尾没跟 qwen 比过**
- **后果**：课本里 **85.8% 的描述是 deepseek 写的**（3448 条"没比过就默认用" + 696 条"裁决判它赢"），只有 **14.2%** 来自强得多的 qwen

- **未证实**：这有没有拉低描述质量 —— **没做过对照**（`data/teacher_v1/` 不在本机，本地无法验证）
