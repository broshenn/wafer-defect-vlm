### 1.3 第一层：整套评测是怎么设计的（学生点的题，5 问）

- **① 为什么五类任务**：一张卷子只测一个角度 —— 分类（认不认得）· 结构化（细节准不准）· 描述（说没说清）· 鲁棒性（稳不稳）· 检索（向量有没有意义）
  - 鲁棒性为什么能判：`qwen35_9b_adapter__report.json` 的 note —— *"class is invariant under resize/recolor/rotate, so a flip is genuine instability"*
  - `all_requests.jsonl` = 1512 = 756（前三卷）+ 756（鲁棒性）
- **② 考卷怎么选、是否隔离**：**本机亲手验的**
  - `core.jsonl` 252 条 `split` 全是 `test`（252/252），test 总共 589 张
  - 我跑的交集：考卷 202 个批次 ∩ train = **空**、∩ val = **空**；252 个样本 ∩ train/val = **空**
  - `results/reports/leak_check.json`：`sample_overlap_with_benchmark` / `lot_overlap_with_benchmark` 三项全空、`lots_straddling_splits: {}`、`passed: true`
  - 选法：每类上限 30（`Near_full` 只 16、`none` 只 26 —— 库不够就全拿），每类内按 `difficulty()` 排序取前 70% 典型 + 后 30% 最难
  - 检索卷：query 用 **seed 3408**（选考卷用 3407，刻意错开），**排除同批次候选**
- **③ 答案来自哪**：**教师模型不在考卷里**
  - 分类 = 数据集原始标签（`label_source: ground_truth`）
  - 结构化 = **原始标签 + 数学算的几何**（`core.jsonl` 的 `gold_source: "ground_truth_label+deterministic_geometry"`）
  - 描述 = **人工写死的词表**（`benchmark.py:19-25` `SHAPE_TERMS` / `FORBIDDEN_TERMS`）
  - 检索 = **规则算的**（`benchmark.py:75-82` `graded_relevance`）
  - `annotator_count: 0`、`agreement: "pending_human_review"`
- **④ 哪些可靠、哪些有争议**：见下面 1.5 的"两格读不通"
- **⑤ 三列是否同条件考试**：**是**
  - 四份原始输出**各 1512 行**（`results/raw_outputs/qwen35_9b_{zero_shot,adapter,grpo}.jsonl`、`..._gspo_g4_lr1e5.jsonl`）
  - 基线日志 `logs/06_baseline_zeroshot.log`：`val_dataset=…/all_requests.jsonl`、`num_rows: 1512`、`RequestConfig(max_tokens=512, temperature=0.0 …)`
  - `scripts/22_eval_adapter.sh` 注释原文：*"This deliberately scores all_requests.jsonl, the same file the zero-shot baseline used, so Base and SFT numbers come from identical prompts."*
  - `scripts/30_eval_grpo.sh` 用同一个脚本、传 `REQUESTS=$BENCH/all_requests.jsonl` → RL 同源
  - **🎯 当时真的排过一次险**（`.hermes/session_logs/A_bf504f7b.md`）：考卷 `13:12:49` 重建过（题面加了 9 个候选词枚举），而基线 `13:11` 左右启动 → 怀疑它加载了**旧题面**。查法：日志的 `num_rows` + 进程实际启动时刻。结论原文：*"Settled — the baseline is valid. … the process started `13:12:51`, two seconds after the 13:12:49 rebuild."*

### 1.7 鲁棒性怎么测 + "没训 ViT 会不会有问题"（学生自己提出的问题）

- **怎么测**（`benchmark.py:100-122`）：252 张各生成 3 个变体 = **756 张**
  - `resize_224`（448→224，最近邻）· `recolor_v1`（`:85-91`，绿 `(0,255,0)→(0,180,30)`、红 `(255,0,0)→(255,80,80)`）· `rotate_90_ccw`（最近邻，不插值）
  - **金标**：类别不变（`gold_transform.class_unchanged: true`），**但钟点方向跟着转**（`:114-115` `rotate_clock`）—— 落实 `AGENTS.md` §7.6
- **判两个数**：准确率（对真值）+ 翻转率（对同一张图的干净答案）
- **我本机重算了一遍，与报告完全一致**（验证了对齐方法）：

| 变体 | Base 准确率／翻转率 | SFT 准确率／翻转率 |
|---|---|---|
| （干净） | 0.2143 | 0.6230 |
| recolor | 0.1865 / 0.1230 | **0.5000 / 0.2857** |
| resize | 0.1706 / 0.1389 | 0.5635 / 0.2381 |
| rotate | 0.2143 / 0.1548 | 0.6230 / 0.2183 |

- **"没训 ViT"的三处代价**（学生问的对）：
  1. **换色掉最狠（−12.3pp）、旋转几乎不掉（±0）** → 模型的判据里"颜色"权重不小，而颜色来自**冻结的 ViT**（我们没机会教它"颜色不是判据"）
     - 逐类别（我算的）：Center −33.3 · Random −23.3 · Edge_Ring −16.7 · Edge_Loc −10.0 · **Near_full −75.0（只 16 条）** · **none +34.6（未解释，不算结论）**
  2. **`resize_224` 正好撤销了第 1 关"放大到 448"的努力** —— 448 时 die = 17.2px ≈ patch 16px；224 时 die = 8.6px → **一个 patch 跨约 2 个 die**
  3. **训练集里一张扰动图都没有**（已核）：`acceptance.json` 的 `train_examples 12876 = 4292 × 3`，多一张都会破
- **⚠️ 但"到底是哪个的锅"分不清**：三个成因都在，**项目没做任何消融** → **"训了 ViT / 加了增强会不会更好"= 未测量**
- **门禁缺一条**（我的观察，非项目结论）：视觉侧训练的四条门禁判据里**没有"鲁棒性"** —— 而鲁棒性恰恰是"冻结视觉塔"最可能暴露的地方
- ⚠️ **翻转率不能跨模型直接比**：我数了 Base 的答案分布 —— **252 条里 185 条（73%）都答 `Random`**；SFT 则散得多（Loc 60/Edge_Loc 55/Edge_Ring 39/…）。**一个反复答同一个词的模型翻转率天然低**，那是"没东西可翻"，不是"稳"

### 1.8 检索（"以图搜图"）怎么测 —— 学生反复要求讲清，最后用一张拼图讲通的

- **背景**（`AGENTS.md` §9）：**生成能力 ≠ 检索能力**，所以单独一张卷子
- **题目**：**就是图本身**（90 张"拿来找的图"）
- **答案**：**一张相关性表**（`retrieval_qrels.jsonl`，22505 行）—— 每行 `{query_id, gallery_id, relevance}`，2 = 很像 / 1 = 同类但不像 / 0 = 不像
- **图库**：**252 张固定不变**（就是考卷那 252 张）
- **规模（我算的）**：90 张拿来找的图 × 252 张图库 = 22680 对，扣掉 **175** 对（90 个"自己" + 85 个"同批次兄弟"）→ **22505** 对；每张平均 **250.06** 个候选
- **🔑 检索时模型不用 `generate()`**（`code/tools/retrieval_rank.py` 全文 105 行，**没有一次 generate**）：
  ```python
  PROBE = "Describe the defect pattern in this wafer map."     # :14
  out = model(**inputs, output_hidden_states=True)             # :51
  hidden = out.hidden_states[-1].float()                       # :52  取最后一层
  pooled = (hidden * mask).sum(1) / mask.sum(1).clamp(min=1)   # :54  平均池化
  normalize(pooled, dim=-1)                                    # :55  归一化
  ```
  - **它是"只想不写"**：喂「图 + 那句固定的话」跑一遍前向，**直接掏内部状态**；模型接下来会写什么，**不看、丢掉**
  - 序列实测（`template_check.json`）：`classification` 总长 **251**、`image_pad_tokens` **196** → 向量里约 78% 是视觉 token
  - **同一句提示词是硬要求**（那句话约 22% 混在向量里）；**换提示词会怎样从未测过**
  - **和 CLIP 的区别**：CLIP 是双塔 + 对比学习；这里是**拿生成模型的隐状态顺手当向量**，**训练时没有任何对比学习目标**
- **排序**：`sims = qvec @ gvec.T`（归一化后点积 = 余弦）→ 降序 → **排除自己 + 排除同批次**（`:88`）→ 取前 50
- **🔒 硬断言**（`:43-49`）：没有 `<|image_pad|>` 就 `raise SystemExit("…refusing to write meaningless rankings")` —— 防"纯文本向量、指标无意义而返回类型正常"
- **🔑 用真实例子讲通的那一张图**：`../学习实验/检索例子.png`
  - 搜索词 `wafer_00023639_020`（**Center**）：模型（Base 与 SFT 都是）**把 `wafer_00017134_013`（Donut）排第 1**
  - **看图就懂了**：搜索词是"绿底中间一团红"，第 1 名是"红环包着一块绿心"—— **空间布局像，但红绿对调** → 模型看的是**像素布局的像**，标准答案是**标签的像**
  - 该搜索词前 10 名里只有 **1（Base）／2（SFT）** 个是相关的
- **分数**：地板 **0.0330** → Base **0.3236** → SFT **0.3873**（最好的 RL run 0.4337）
- **为什么"不能宣称 SFT 优化了检索"**：① 训练时**没有任何对比学习目标**（提升是副产品）② 检索列走 **merged**、生成列走 **adapter**（两条载入路径，见 1.9）
- **⚠️ 本机缺**：`benchmark/robustness_images/`（756 张扰动图）→ **能重算鲁棒性分数，不能重跑鲁棒性推理**

### 1.9 第 8 关 · adapter vs merged 等价性 —— **我在课上先讲错、后来当场纠正**

- 初版说法（**错**）："只对上 0.4667，是个未解决的悬案"
- **纠正**：同目录还有 `results/merge_check/precision_floor.json` —— **同一个模型、只换精度**的一致率是 **0.4333**
  - `equivalence.json`：`exact_matches 28/60 = 0.4667`、`functional_agreement 0.7667`
  - `precision_floor.json`：`exact_matches 26/60 = 0.4333`、`functional_agreement 0.7000`
  - `equivalence.json` 的 `criterion_note` 原文：*"exact_agreement is a numeric-reproducibility measure, **not a correctness one** … **Compare functional_agreement against the same-model precision floor before concluding the merge changed behaviour.**"*
  - **结论：merge 没有改变行为**，`AGENTS.md` §12 那条验收（"Adapter 推理和合并后推理结果基本一致"）按项目自己的判据是**过的**
- **我的错在哪**：我引用了 `FINAL_REPORT` §6b 那一行（只写 0.4667、**没引用旁边的地板**），就当成"问题"讲了 → 已记为 `踩雷记录` **C09**

## 六、下一次开场建议（照着说就行）

> **开场话术**：
> "考试那一关走完了 —— 你现在能讲清五张卷子怎么出、怎么判、分数怎么读，也知道 `0.6230` 背后压着几层限定语。
> 今天我们进**第 9 关：强化学习后训练**。前面 SFT 是'抄答案'，这一步是'自己答题、按得分调整'。
> 项目跑了 12 个 run，最后**一个都没能显著超过 SFT**，而且里面有两个很值得学的坑。"

**第 9/10 关的目标**：理解 GRPO/GSPO 在做什么、12 个 run 的实验网格、**两个混淆**、以及为什么最终"保留 SFT"

**核心代码/材料入口**：

| 讲什么 | 位置 |
|---|---|
| 奖励函数（四个确定性规则） | `code/tools/wafer_grpo_plugin.py` |
| 训练脚本 | `code/projects/wafer-defect-vlm/scripts/24_train_grpo.sh`、`29_grpo_train.sh` |
| 各 run 的曲线 | `results/curves/*.jsonl`（11 个 RL run + SFT） |
| 训练结果摘要 | `results/reports/*_train_result.json` |
| **配对显著性（本关最硬的一份）** | `results/reports/paired_significance.json` |
| 有效批次修正 | `results/reports/effective_batch_correction.json` |
| KL 与长度混淆 | `results/reports/kl_length_confound.json` |
| 主表 | `../docs/FINAL_REPORT.md` §7 · `../docs/LIMITATIONS.md` §5.2 |

**这一关的三个看点**：

1. **奖励是什么** —— 四个**确定性规则**（不用任何 LLM 当评委），以及"零优势步"（组内奖励全相同 → 优势为 0 → 白跑一步）为什么随组大小下降
2. **两个混淆** —— ① 层级（token/sequence）与组大小**绑死**；② **有效批次 = 组大小²**（因为梯度累积被设成等于组大小）→ 于是全篇**唯一干净的单变量对照是学习率**
3. **判定** —— 按论文 §8.11 的分支，没有一个 run 显著超过 SFT → **保留 SFT，不宣称 RL 有效**；且 `lr 5e-5` 那几个**显著更差**

**建议节奏**：约 2~3 轮。**开场先讲奖励与"零优势步"**（好懂、有直觉），再讲实验网格与两个混淆，最后讲判定与"论文的 +0.009"对照。

**⚠️ 讲这一段必须守的**：
- 每个 RL run 的准确率**都要先跟 SFT 配对比**，不许只报点估计（`踩雷记录` A10）
- **有效批次 = G²** 这个混淆必须先讲，否则"组大小→更好"会被误读成结论（A09）
- `lr 5e-5` 的下降是**显著**的，别写成"噪声"；反过来 `lr 1e-5` 的微涨是**不显著**的，别写成"有提升"
- 论文的 **+0.009** 是 **LLM-Judge** 指标，与本项目的确定性规则**不是同一把尺子，数字不可直接比**
