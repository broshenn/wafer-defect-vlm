# 给Claude：与当前RL并行的数据扩容准备，仅CPU

**Codex，2026-10-06。** 用户要求后续数据不能少，并询问两天内形成实验结果和简历材料的可行性。本任务准备扩容数据，不等待RL成绩，不改变当前RL配置，不启动新的GPU训练。训练相关数据处理在学校本人工作区进行；Codex本地只读库存核对。

## 1. 已核对的库存

本地manifest有5904个唯一ID，data/images有5904个同名PNG，逐ID集合一致、无缺图或清单外PNG。manifest标为ground_truth的类别行5904，原split为train4721 / val594 / test589。这个核对证明本地文件集合齐，不证明学校已传齐，也不证明描述/几何/人工gold齐。

manifest保留历史服务器image_path，不能把这些绝对路径在Windows不存在当图片缺失；本地对应data/images/<sample_id>.png，学校路径重映射另存并核图片hash，不覆盖manifest。既有训练180只作为小规模基线。

## 2. 可立即并行的准备

- 核学校本人数据目录和已上传图片库存。缺图时补传所需公开PNG及manifest/指纹；复用已有图片，两端SHA256，报告字节量。不读取他人目录，不重下基座或装环境，不调用教师API，不让ZCode重标全量。
- 从原train划分、可信原类别选扩容样本，seed3407。保留旧train180作为规模曲线的起点；新样本与旧180关系显式记录。排当前RL池及其lot（只需已冻结清单，不需训练结果）、开发/最终保留集、benchmark根晶圆及lot、其他被用于调试的非训练样本及lot。
- 当前RL池清单尚不可得时，可先准备库存、排除候选和dry-run配额，不把未知池当空集宣布冻结完成。获得清单后做最后隔离；这项依赖是清单，不是RL成绩。
- 目标准备千张级主训练候选，首选1440条唯一晶圆；同时形成180/360/720/1440的嵌套规模清单。数据源不足时如实减量，不复制原图或增强图充作新增唯一晶圆，不从val/test凑数。
- 类别尽量平衡，优先跨lot、多种原矩阵shape和缺陷密度分层，不凭目测或模型答对选样。Near_full在原train仅127条，排除后更少，不能承诺每类160；保存各类可用图/lot、实际配额、补足其它类的规则与不平衡限制。优先每lot一张；若需同lot多晶圆，事前锁上限并报告。
- 只用可信原始类别生成扩容分类SFT数据，不用教师预测替类别gold，不调用模型给自己打标签。保留类别来源、sample_id、lot、图hash、选样层和题面hash。
- 用户/系统题面沿当前分类题原样；assistant仅类别JSON。生成供模型推理的清单必须无答案；类别gold仅用于训练assistant或独立评分，防止metadata进入模板prompt。

## 3. 评测与描述对照同时准备

现有val84保持固定，用于和旧结果桥接。先盘点原val剩余可用图和未用于调试的test候选，给出扩开发集/最终确认集的覆盖建议；不要修改原split、旧benchmark或自动把已分析样本称全新盲测。

逐类列最终确认候选数和lot数。尤其Near_full原test只有16条，而旧benchmark已包含16条；必须核ID/lot，不能假设当前库存还够新九类独立最终考卷。缺乏未接触的稀缺类时标明，并提出获取更多公开原始数据/审核的后续方案，不先重命名旧集解除污染。

描述/几何对照另给实际可用ID交集和来源：目前158条描述候选、90条结构化候选、22条描述隔离不能当180条完整描述。A/B/C必须同图、同评测协议，筛选依赖与GLM+Codex修改来源披露；不要只筛C，其他组用全量再称公平。几何事实缺失、不适用和可靠性需逐字段记录；本任务不自动启动这些训练或编造人工审核。

## 4. 验收与资源估算

脚本默认dry-run、固定seed、拒覆盖、resume字节稳定，产物只写本人新目录。独立检查完整manifest的val/test非空、派生ID根映射、全部跨split/保留池lot交集、ID与PNG一致、分层数量、题面/来源和hash；对空集合、未知ID、同lot跨split合成冲突做失败测试。

按当前单卡实测速度，估算扩容训练所需优化步和设备分钟。必须保证目标规模实际被呈现：60步×有效batch4约240次样本呈现，不能称1440条已全部学习。给出固定数据呈现预算的比较方案和epoch充分覆盖方案，说明二者回答不同问题。估算不是实际成绩。

当前累计GPU上限180，本任务新增GPU授权为0；不得因准备好1440条就直接启动更长训练。回交扩容所需具体GPU预算和当前RL真实账，供Codex下一步裁决。CPU预处理/上传/校验单独记，不占用或创建占位GPU。

按六项格式交付：实测库存、各类有效候选、嵌套清单/源标签/题面/图片指纹、排除池与未知项、独立校验、学校上传状况、数据呈现及预算估计。仅数据准备完成不写训练完成。结果由用户转交Codex，不直接给其它会话发消息。
