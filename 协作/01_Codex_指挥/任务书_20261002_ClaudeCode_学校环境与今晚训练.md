## 2. 只读核查实际环境

成功 SSH 后，先核对登录身份和主机是否匹配接入资料，身份值不要写进公开仓库。然后检查：

- `nvidia-smi`：型号、显存、驱动、各卡当前占用；空闲不等于分配给我们。确认可使用的 GPU/时段或调度规则后再启动。
- RAM、个人已分配存储的容量/可用空间/配额、个人工作区现状。只查自己的目录，不遍历他人文件或进入他人容器。
- Python、torch、CUDA、transformers、ms-swift、PEFT、bitsandbytes、tmux/调度器是否存在及版本。只打印白名单版本，不能打印完整环境变量。
- 个人获准模型目录是否已有完整 `Qwen/Qwen3.5-9B` 权重及 revision。不能沿用旧 AutoDL 路径或把历史硬件记录当学校实测。
- 已分配存储、容量/配额、备份安排及环境管理方式是否明确。新增大体积环境/模型前按服务器 skill 确认这些约定；优先复用个人已有环境和权重。

有现成环境时先验证，不一上来重装。需要新环境只建在个人获准大盘目录，不用系统 Python、不执行 sudo、不改公共容器。模型下载在学校端完成，固定具体 revision；不从 Mac 搬整套权重，不使用 latest 作为记录。

输出脱敏的 `environment_report.md`：实际设备与版本、是否具备 SSH 执行/模型/环境/GPU 使用条件，未知项如实写。远端真实路径和身份只留仓库外私有运行记录；项目报告使用路径别名。

## 3. 同时做本地训练准备，不等登录

新产物只在 `协作/02_ClaudeCode_实操/学校训练准备_20261002_<时间>/`。保护历史 `code/ docs/ results/ benchmark/`，不改其他 Agent 目录。

准备一个**标签监督 SFT-A 技术基线**：

- 数据源仅公开 `data/manifest.jsonl` 与原位置 PNG；只用 `label_source=ground_truth` 的原始 `failure_type`，不读取预测标签充作真值。
- 训练主清单：九类各二十张，共一百八十张 train；seed=3407，同一 lot 留在同一划分。另从 validation 选九类各两张，共十八张开发验证样本；与训练、冻结 benchmark 的 lot 隔离。
- 二十条训练小测试是主训练清单的子集：九类各两条，再固定种子补两条不同晶圆。报告唯一图片数、lot 数、重复和丢弃原因。库存不足或 lot 隔离失败时停止该数据集，不偷偷放宽。
- 排除正在进行的 ZCode 十八张开发样本及其 lot，防止训练准备反馈进入该标注会话。不要读取其新回答或给它逐图提示。
- ms-swift JSONL 使用 `messages + images`。输入只给图片和统一分类问题，回答只含可信类别，例如 `{"defect_class":"Center"}`；不伪造 morphology、方向、尺寸、Caption 或专家审核。
- 固定训练/推理题面：识别九类主要图案，不能判断时允许 unknown，只输出 defect_class 的 JSON。输入不得含原类别或答案提示。此题面与 GLM 七字段试标题面不同，因此本训练不能冒称已做 GLM 同题能力对照。
- 导出脚本支持 dry-run、固定 seed、幂等与断点；图片不在本地复制。传输时只打包选定的公开 PNG、数据 JSONL 和必要代码，远端生成路径版本并保存前后指纹；不上传整个仓库、凭据或个人配置。
- 训练前实际打印 train/val/test/benchmark lot 交集，非空立即失败。保存数据版本、SHA256、标签来源和图片指纹。

任务书没有授权制造新的人工金标；所有评测保持开发/草稿状态。

## 4. 执行配置与预算

最多使用**一张已获准 GPU**，本任务累计训练/推理上限 **两 GPU 小时**；按实际开始/结束累计，下载和环境准备另记录耗时。无新增付费模型调用，不购买云 GPU，不改共享服务器配置。

优先使用 ms-swift 支持的冻结视觉侧 LoRA：rank=16、alpha=32、dropout=0.05、LLM all-linear、冻结 ViT/aligner、学习率 1e-4、BF16、max_length=2048、图像 token 起点 256、seed=3407、gradient checkpointing。具体参数必须对照**实际固定版本**的 `swift sft --help` 和模型模板；历史脚本只能参考，不能直接带旧路径执行。

若 BF16 确实放不下，可在同一张卡用该版本支持的 4-bit QLoRA，另记配置和原因；不同时开两套，不扩大 GPU 数。版本无法支持 Qwen3.5 的视觉模板时先修兼容性，不换成纯文本基座。

### A. 未训练基座与接线检查

先保存基座在开发验证十八张上的原始分类输出、提示词及生成参数；不使用 Adapter，不声明已经完成完整 Benchmark。实际解码一条多模态模板，确认有视觉输入、问题无答案泄漏、loss mask 只训练回答；核对可训练参数。

### B. 二十条 SFT 小测试

固定 max_steps=20、micro-batch=1、gradient_accumulation=1，另存输出。真实观察有限 loss、参数/LoRA 更新、实际图片输入和 checkpoint 保存；不以“进程启动”或“脚本退出 0”代替训练通过。若技术上失败，保存原始错误，在预算内修复后再试；不无限重试。

小测试结束加载 Adapter，用几张明确记录为 train/dev 的图生成分类 JSON，保存原答与加载方式。合并是否进行取决于实际内存和部署需求；未合并就写 not run，不能把加载 Adapter 冒称合并验证。

### C. 通过即启动标签基线，不再等中途批准

小测试通过、数据与环境条件有效、剩余预算足够时，**直接启动一百八十张 SFT-A**：max_steps=60、micro-batch=1、gradient_accumulation=4，其余冻结配置一致。它按步数停止，不同时声称只训练一 epoch。

用独立新输出目录，固定在最终第六十步选择 checkpoint，开发验证只做诊断，不挑最好模型。训练后在相同开发验证样本/分类题面/解码设置下保存 Adapter 原始输出，报告 loss、分类/格式、每类结果、显存、实际步数与耗时；不宣称代表正式测试或完整描述能力。

用 tmux 或实验室调度器保留长任务。立即停止条件：GPU 未获分配、存储/环境权限不明、lot 泄漏、错误模型/视觉模板、非有限 loss、重复 OOM 经一次合理缩减后仍失败、两 GPU 小时预算到达或共享资源明显受扰。不杀别人的任务。
