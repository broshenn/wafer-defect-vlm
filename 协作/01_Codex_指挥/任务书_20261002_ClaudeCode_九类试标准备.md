## 2. 固定输入与选样规则

- 来源：本地 `data/manifest.jsonl`、`data/images/`；只有公开晶圆图。
- 只使用 `split=train`、`label_source=ground_truth` 的可信原标签，九类标签统一为 Center、Donut、Edge_Loc、Edge_Ring、Loc、Near_full、Random、Scratch、none。保留原始值与正规化映射，不改原清单。
- 排除所有 `benchmark/` 样本及其 lot，以及与 validation/test lot 重叠的候选。检查全清单的 lot 交集；若发现冲突停止，不静默修正。
- 排除此前 Kimi / GLM 实际试标过的样本及其 lot，包括 `wafer_00016894_009` 和 `wafer_00017178_007`。从历史结果文件提取完整排除表，不能只凭这两个例子。
- 每类候选按 sample_id 排序，seed=3407 抽样，九张来自不同 lot。图片必须存在、唯一且指纹互不重复；颜色、PNG 与 448×448 格式通过检查。选不齐时如实报告，不能回填 test、旧 benchmark 或不可信标签。
- 最终顺序按同一个固定 seed 打乱；不按类别排序，不在盲清单里透露抽样类别或难度。不得给 ZCode 指定某个序号应是什么类。
- 图片直接引用原位置，不复制、不搬动。清单里写本机路径，不能复制旧 manifest 中的服务器私有路径。

## 3. 输出与保密边界

新文件写入自己的新目录，例如 `协作/02_ClaudeCode_实操/准备_20261002_九类试标/`；目录若存在就另建带时间戳的新目录，不能覆盖。

交付这些文件：

1. `blind_inputs.jsonl`：逐行仅含 `item_id`（例如 item_001）、`sample_id`、原位置 `image_path`、`image_sha256`。无标签、lot、split、几何答案、难度或选图观察。图片文件名不得包含答案。
2. `audit_selected.jsonl`：仅供 Codex 后验核对，保存真实原标签、来源行号、split、lot、排除与正规化依据。明确禁止 ZCode 读取本文件。
3. `plan.json`：计划数量、固定 seed、盲清单顺序与 SHA256、数据文件 SHA256、提示词文件字节 SHA256 和统一 LF 文本 SHA256、选样规则版本、排除清单来源、逐项检查状态。
4. `prepare_report.md`：合格交接六项；区分计划与实测。附样本/lot/图像指纹隔离检查、类覆盖、排除原因、已知限制和下一步。不要将 audit 标签拷进给 ZCode 的说明。
5. 可复用准备或校验脚本：支持 dry-run、固定 seed、幂等和避免覆盖。可安全复用历史纯格式校验逻辑，不导入/运行会读取代理配置或发请求的入口，不复制凭据配置。

允许读取历史公开试标结果以建立排除名单；不读取 WorkBuddy 配置、密钥、登录 Token 或完整环境变量。不向任何模型发送图片。

## 4. 预算、成功与停止条件

- 外部模型请求预算 **0 次**；GPU 训练与付费调用 **0 次**。
- 成功：九类各一张、不同训练 lot、无基准或验证/测试 lot 交集、无已看过样本/lot、图像与数据指纹齐全、盲清单无答案、提示词版本锁定。
- 停止：候选不足、标签来源不可信、lot 冲突、指纹重复、图像不合格、无法可靠映射旧路径或需要密钥。保留诊断与已有产物，不自行放宽规则。
- 只读检查和必要小型验证完成后停止，不启动 ZCode、不自动扩大样本、不上传学校服务器。
