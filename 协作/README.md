## 二、四条规则

### 规则 1 · 只在自己的目录里写

**新文件一律写进自己编号的目录。** 不往别人的目录写，不往根目录写。

### 规则 2 · 不覆盖别人的东西

同一目录里已有文件**不删不改**。要修正就在自己目录里写一份带日期的新版，并说明改了什么。

### 规则 3 · 共享文档改动要记名

以下文件**不属于任何单个 agent**，改动必须在提交信息或文件里写明**是谁改的、为什么**：

| 文件 | 是什么 |
|---|---|
| `AGENTS.md` | 项目宪章。§1–13 事前计划，§14–18 事后补记 |
| `HANDOFF.md` | 项目总交接 |
| `MASTER_交接.md` | 总索引与阅读路径 |
| `踩雷记录.md` | **一切问题的归档处**（见规则 4） |
| `重做计划/0[1-4]*` | 实验方案（**指挥会话的地盘**，但改动要记名） |
| `学习记录/`、`docs/`、`results/`、`benchmark/`、`code/` | 历史产物，**只读**（`code/` 与 `docs/` 是服务器快照） |

### 规则 4 · 发现问题记进 `踩雷记录.md`

这是用户 2026-09-27 定的规矩：**"以后有问题的就记在这个文件里面"**。
分 A（项目已记录）/ B（新发现）/ **C（自己犯的错）** 三类。**C 类最值钱**——它记的是"agent 会怎么骗人"。

**注意**：`kimi_k3_cost_test/执行Agent交接_20261001.md` §6 曾要求"不要写进 `踩雷记录.md`"——
那是**那一次任务**的临时约束（怕执行方擅自改写）。**规则 4 是常态要求**，两者不冲突：常态要记。
若某次任务明确禁止，以任务书为准。

## 四、交接格式（给下一个 agent 或指挥会话）

一份合格的交接，**六件都要有**（照 `kimi_k3_cost_test/诊断交付_20261001-234717/诊断交付.md` 的格式）：

| # | 内容 |
|---|---|
| 1 | **核实了什么** —— 结论 + `文件:行号`，**区分事实与解释** |
| 2 | **仍未知什么** —— 明确写"未查明"，不猜 |
| 3 | **改了什么** —— 只列必要改动；**没有改动也明说** |
| 4 | **下一步最小动作** —— 标明**未运行** |
| 5 | **证据路径** |
| 6 | **实际调用与消耗** —— 用了多少付费额度；若发生偏离如实报告 |

**三条通用纪律**（项目自己的）：

1. **数字必须能追到出处**；追不到的标"未核实"。
2. **结论分三层**：① 能核对的事实 ② 你的解释（可能错）③ 未证实 / 未测量。**`not run` 不是 0。**
3. **宁可用一个能跑的检查器，也不要读一遍就宣布通过。**
