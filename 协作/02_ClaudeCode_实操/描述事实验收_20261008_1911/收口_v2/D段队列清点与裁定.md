## 三、审计指出的四个缺口，v2 逐条修（**仅另存实现，未据此重跑**）

| # | 缺口（Codex 独立审计） | v2 怎么修 | 离线验证 |
|---|---|---|---|
| 1 | `720×30 秒 = 6 小时`，不是承诺的 40 分钟 | 改成**绝对截止时间戳**由调用方传入，脚本**不再暗含任何时长** | 边界 1 |
| 2 | UUID 查询成功 ≠ 进程查询成功；查询失败→空输出→`grep -c` 得 0→**被当成空卡** | **每次查询都判返回码**，「查询失败」与「确实是 0 个进程」严格区分 | 边界 2 |
| 3 | **原子锁后未复查占用** | 锁后**再查一次**，被占就释放锁走人 | 边界 3 |
| 4 | Python 失败后仍 echo「完成」、最终返回 0；queue 未透传 rc | 返回码**分四态**：0 全成功 / 1 有失败 / 7 预算耗尽有未启动 / 4 一个都没跑 | 边界 4、5 |

另按合同补的：
- **共享同一累计计时器**：三个模型**串行**跑在一张卡上，
  从**子进程启动**（含 CUDA 上下文与模型加载）到**进程退出释放**，
  **失败与已跑部分全部计入**；耗尽即停，写**部分完成**，不写完整成功。
- **查询整体异常即停止派发**（连续失败达阈值），不反复堆探针。

### 离线模拟结果：**18/18 通过**（不碰 GPU）

`模拟_五边界.sh` 把 `nvidia-smi` 与 `python` 注入替换成假的、`WS_ROOT` 指向沙箱 ——
**被模拟的就是真正要跑的那份脚本，生产路径一行没改**。

| 边界 | 断言 | 结果 |
|---|---|---|
| 1 无卡 | 等满截止后放弃、**不启动**、返回 4 | ✓ |
| 2 查询失败 | 达阈值即停止派发、返回 6、**不堆探针** | ✓ |
| 3 锁后占用 | **放弃该卡并释放锁**、不启动 | ✓ |
| 4 子进程非零 | 记 FAILED、**耗时计入预算**、返回 1 | ✓ |
| 5 预算耗尽 | 剩余记 **NOT_RUN**、返回 7（**部分完成不谎报成功**） | ✓ |

> 模拟过程本身也修掉了两个**我自己的**错误：假 `nvidia-smi` 没解析 `-i` 的卡号
> （导致所有卡都被当成占满）、以及沙箱里漏放 v2 脚本（返回 127）。
> 这正是「用一个能跑的检查器，而不是读一遍就宣布通过」的意义。
