### 二、唯一必要实现修复：v3 运行中硬截止

你指出 v2 只在**模型之间**查预算、当前进程无 timeout，
且「预算 3 秒实际记 4 秒」说明 18/18 没证明 40 是硬上限。**已另存 v3 并逐条修：**

| 你的要求 | v3 实现 |
|---|---|
| 单调时钟 + 全局 D 截止 | `time.monotonic()` 记绝对截止 |
| 当前子进程组的剩余时间硬超时 | `Popen(start_new_session=True)` 给**剩余时间**；到点 `SIGTERM` **整组** → `SIGKILL` **整组** |
| 终止与 CUDA 释放宽限也在 40 内 | `--grace`（本次 60s）从预算里扣，不是额外送 |
| 超时后留已 flush 原答 / 已用时间 / 未执行计数 | 账本逐行含状态、秒数、备注；评测脚本本就逐条 flush |
| 退出后核 GPU 释放 | 退出前查该卡进程数，非 0 会置非零返回码 |
| 失败码照实传播 | rc=0/1/3/7/4 四态，优先顺序写进注释 |

**离线补了你点名的两个反例（`模拟_v3硬截止.py`），12/12 通过**：
- **单个假推理睡 600 秒** → **6.1 秒被杀**（预算 8s、宽限 2s，实测 6.1s）
- **假推理创建子进程** → **父子整组杀干净，pgrep 查无残留**
- 另含原有四类：无卡 / 查询失败 / 锁后占用 / 子进程非零

**实跑验证**：**170 秒 / 2100 秒上限，未触及截止；退出后 GPU 残留 0。**

**租机只有一张分配卡**：脚本按「现场查询成功 + UUID 有效 + 无人占用」直接锁该卡，
