## 2. 撤回：「教师抄输入、没有看图」

### 原报告的断言与其出处

`协作/02_ClaudeCode_实操/夜间扩容_20261008_0244/数据/训练数据_N3072.json` 的
`字段取舍.不用的理由` 字段写着：

> 「实测 4291/4291（100%）与给教师的几何特征逐位相同——**teacher 是抄输入不是看图**」

### 为什么这个推理是错的

`code/projects/wafer-defect-vlm/src/wafer_vlm/curate.py:238` 的 `structured_target()`：

```python
target = {key: result.get(key) for key in STRUCTURED_FIELDS}   # 248：先抄教师结果
if geometry_gold:
    features = record.get("features", {})
    target["defect_type"]    = record["failure_type"]           # 251
    target["radial_zone"]    = features.get("radial_zone")      # 252
    target["clock_direction"]= features.get("clock_sector")     # 253
    target["size_r"]         = features.get("defect_extent_r")  # 254
```

而 `logs/07_train.sh:29` 明确启用了 `"geometry_gold_structure": true`
（并在同行注明「the four geometry-scored structured fields are written from
trusted label + features」）。

**我比较的是「最终 structured 目标」和「给教师的特征」**——
而最终目标里那四个字段**恰恰是被程序直接覆盖成特征值的**。
所以 4291/4291 相同是这个覆盖机制的**必然结果**，
**完全不携带关于教师输出的信息**：教师到底是照抄、还是看图后恰好一致，
从这份数据里**无法分辨**。

`code/projects/wafer-defect-vlm/tests/test_curate_arbitrate.py:73`
还有一条单元测试就叫 `test_geometry_gold_overrides_only_the_scored_geometry_fields`——
这个机制在仓库里是**有测试、有文档**的，我读漏了。

### 更正后的说法

- **撤回**「教师抄输入、没有看图」以及由它推出的任何结论。
- 那四个字段（`radial_zone` / `clock_direction` / `size_r` / `defect_type`）
  在本轮训练中**仍然不用**，但**理由换成**：
  它们不是教师的判断，而是**程序写入的几何特征**，用它们做监督等于把
  「本项目自己算的几何」当成视觉真值 —— 而 `radial_zone` 已知是**质心**定义，
  与「主要缺陷区域」不是一回事。这是**口径理由**，不是「教师作弊」的证据。
- `shape` / `caption_zh` 来自教师结果。但教师**同时收到了图片和 features**，
  且 `shape` 还经过**类别白名单筛选** —— 因此它们只能称为
  **模型辅助候选**，**不能**由「不在 features 字典里」就证明是纯视觉判断。
- **决断性检验：not run。** 真正的检验是拿**保存的教师原始结果**去比 features。
  那批 `teacher_v1/primary_deepseek.jsonl` / `secondary_qwen.jsonl` 只存在于
  现已关机的租用实例上；本次在两台学校服务器上搜索
  （`find … -name "primary_deepseek*" -o -name "secondary_qwen*"`）**命中 0**。
  **没测**不等于「教师没抄」，也不等于「教师抄了」——这一项**悬空**。
- **本轮字段取舍与训练结果不变，不因此重训。**

### 三个数**不可互相替代、不可混名**

- **JSON 可解析率**：输出是不是一个合法的 JSON 对象。微调后五个模型里四个是 102/102。
- **完整 schema 通过**：七键齐备、无多余键、枚举合法、`extent_r` 必须是**真 JSON null**。
  `L` 有 4 条 `radial_zone` 越界（如 `upper/middle/edge/global/none/unknown` 这种把
  所有选项抄一遍的），`D-3408` 是唯一 102/102 的。
- **`clock_direction` 字面 `"null"`**：写成了**字符串** `"null"` 而不是 JSON `null`。
  **类型检查会放过它**（协议允许字符串），但它不符合「无可靠方向时填 JSON null」的**约定**。
  `L` 高达 96/102 —— **这是本轮最整齐的一处约定违例**，
  说明它在训练数据里就把「无方向」学成了字符串。
  **这是格式约定问题，不是事实错误**；按 Codex 意见**另列，不改原答**。

> **口径来源**：上表 schema 判定与各原答里冻结的 `schema_ok` / `schema_problems`

1. **微调极其有效**：Base → L 在两套题面、两个指标上都不跨 0，幅度 0.87–0.92。

4. ⚠️ **仍不能推广为「描述监督普遍有害」**：单种子层面 + 一种数据构造 + 单个 84 张开发集。
