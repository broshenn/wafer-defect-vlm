### F2. `clock_direction` 的约定违例是本轮**最整齐**的一处格式问题

| 模型 | 写成字符串 `"null"` |
|---|---|
| `L-N3072-3407` | **96 / 102** |
| `D-N3072-3407` | 52 / 102 |
| `D-N3072-3408` | 64 / 102 |

值得注意：**只学类别的 `L` 犯这个错最严重**（96/102，其余全部模型为 52–64）。
而 `L` 的训练题面（`数据/L_N3072.jsonl`）**从头到尾没出现过 `clock_direction` 这个词**
—— 它只被训练输出 `{"defect_class": …}`（题面：「`defect_class` 为必填…
可以在同一个对象里附加你从图中实际看到的判读依据字段」）。

→ 但**来源机制未验证**。候选解释至少有两个：
  ① **题面诱导**——评测题面里那句
     `"clock_direction":"可靠识别局部缺陷方向时写简短钟点方向，否则 null"`，
     `null` 没加引号，而同一层 JSON 里别的值都带引号；
  ② **基座已有的输出习惯**——未微调的 `Base` 在能解析的那 28 条里
     `clock_direction` 全是**真 JSON null**，所以「写 `null`」这件事
     也可能本来就来自基座。

**不能断言只来自题面。** 本轮**未做提示词消融**（换一种题面写法看违例率是否变化），
所以不为此另开实验、不改主成绩。

### F3. 完整 schema 与 JSON 可解析是**两个数**

`D-N3072-3408` 是唯一 **102/102 完整 schema** 的模型；

→ 「JSON 可解析 100%」**不等于**「七字段合法 100%」，两者不可互相替代。

### F4. dev18 的 18 张原图**全部含红像素**

最少 16,973 个、最多 149,605 个纯红像素（有效像素约 15.3–16.0 万）。
→ D 段诊断里「原图」条件的 gold **恒为 true**，它只能测**真正例率**，
**测不了假阳性**。这一点在设计阶段就写进报告，避免事后被误读成「准确率 100%」。

### F5. lot 的真实结构（**这一条我先写错、又改对了，过程留证**）

**我最初的写法是错的**：我看到评测 102 张的 lot 表是「102 张 / 102 个 lot」，
就写下「lot 由 sample_id 派生、一图一 lot」。**这个推论是错的。**
起因是我只看了那 102 行，没去看更宽的 manifest。

**实际结构**（`data/manifest.jsonl`，历史快照，5904 行）：

| 事实 | 数值 |
|---|---|
| 晶圆数 / 唯一 lot 数 | 5904 / **3822** |
| **单个 lot 最多含多少晶圆** | **24** |
| lot 名是否可由 `sample_id` 推出 | **是**（5904/5904）——因为 `sample_id` 本身就是 `wafer_<lot号>_<lot内晶圆序号>` |
| **跨 split 的 lot 数** | **0 / 3822** ✓ |

→ **id 命名规则**让 lot 可由 sample_id 推出，**但 lot 确实把多张晶圆聚在一起**。
项目的 lot 隔离约束是**真实且有意义的**，不是同义反复。

**那为什么评测 102 是「一图一 lot」？**
因为它恰好是从 val（594 行 / 372 lot）里按类别平衡抽的 102 张，
抽到的正好是 102 个不同 lot。**这只是这批子集的属性，不是全局规律。**

**对统计口径的影响**：
- 在**这 102 张**上，按 lot 重抽 ≈ 按样本重抽 —— 它**不构成第二个独立视角**。
  这一点我原来的话（「不构成额外保护」）**结论对、理由错**。
- 但**训练集与评测集之间**的 lot 隔离是**真的**，且已独立核过：

| 检查 | 结果 |
|---|---|
| 训练 3072 张（**2171 个 lot**）∩ 评测 102 张（**102 个 lot**） | **样本 0、lot 0** ✓ |
| 训练/评测样本在历史 manifest 中的缺失数 | 0 / 0（两边都能对上） |

**未核实部分**（保留）：历史 manifest 的 lot 字段是**公开数据集自带**还是
**项目派生**，本轮未追溯；「没测到」不等于「不存在」。

## 二、本轮的实质错误（我自己的）

### E1. `radial_zone` 枚举用错 → 本地复算的 schema 虚低 25 条

我凭印象把协议里的 `radial_zone` 枚举写成 `{center, edge, global}` 三值，
实际冻结协议（`eval_7f_5090.py:62`）是
`["center","middle","edge","global","none","unknown"]` **六值**。
结果 `L` 的 schema 通过数我算成 **73/102**，而运行期冻结值是 **98/102**。

**怎么发现的**：我没有直接采信自己的复算，而是拿它与**各原答里冻结的
`schema_ok` / `schema_problems` 逐条比对**（5 模型 × 102 条），
不一致 25 条全部是 `radial_zone越界` → 定位到枚举写窄了。
修好后不一致 **0**。

**教训**：**枚举定义必须从冻结协议里读出来，不能凭印象写。**
并且「自己复算的数」一定要和一个**独立冻结过的数**对一遍。

### E2. `except ValueError` 排在 `JSONDecodeError` 前面 —— **重犯历史错误**

`JSONDecodeError` 是 `ValueError` 的子类，前面的分支把后面的吞掉了，
导致**截断**被误判成 `duplicate_key`。
这个坑我在**之前的会话里已经踩过一次并修过**，这次为 D 段写新解析器时**又写错了**。

**修法**：调整捕获顺序，并在代码里留了一行注释说明为什么顺序不能换。
**教训**：这类「Python 异常层级」的坑，修一次不够——
要在**新写的每一个同类解析器**上重新检查，光记住没用。

### E3. Base 去围栏诊断：把「没有围栏」也算失败

我最初写的诊断口径是「剥不掉围栏 → 记为 unknown」，
于是 `Base` 七字段诊断分算成 **11/84**，而 Codex 的是 **15/84**。
差的 4 条正是**本来就严格可解析**的那些——它们没有围栏，不该被丢掉。

**修法**：改成**回退**口径（剥不掉就用原严格结果）。
**教训**：诊断口径和主口径的**边界**要写清楚，
「诊断更宽」不等于「诊断把主口径的结果也作废」。

### E4. 资源账重复计入 42.90（原报告）

`资源账_实测.json` 把 A/B/C 的 42.90 既算进「本阶段之前已报 383.53」，
又在今晚各段里再列一次。已在更正版报告 §8 订正为 937.50 / 1321.03 / 478.97。

### E5. 队列判据（**这次没重犯，但要留证**）

`chain_one.sh` 里那句 `|| [ "$o" = "<本人账号>" ]`（「卡上只有我自己的进程也算空闲」）
是 2026-10-08 三条链同时 OOM 的直接原因。
本轮新写的 `queue_existence.sh` **只认 `n == 0`**，
并在脚本注释里**显式点名那句旧判据**，防止以后有人再抄回去。
另外加了 `mkdir` **原子锁**防止三个队列抢同一张卡。

### E6. 差点把一个**只看 102 行的推论**当成全局事实（见 F5）

我看到评测 102 张的 lot 表是「102 张 / 102 lot」，就写下
「lot 由 sample_id 派生、一图一 lot」，并准备据此宣布
「项目的 lot 隔离是同义反复、不是额外保护」。**这个推论是错的。**

**为什么错**：我只看了**那 102 行**，没去翻更宽的 `data/manifest.jsonl`。
翻进去就发现 5904 张晶圆分成 **3822 个 lot**，**单个 lot 最多 24 张晶圆**，
且 **0 个 lot 跨 split** —— lot 隔离是真实且有效的约束。

**教训**：**别拿一个子集的形状去断言全局的结构。**
样本子集往往是按类别平衡抽的，它的 lot 分布**不代表**总体的 lot 分布。
判断「某个约束是不是同义反复」之前，必须去看**定义该约束的那份数据**，
而不是看被约束之后的结果。

**这个错误没有进最终报告**（在提交前被自查发现并改掉了），
但按项目惯例仍应留证 —— 因为它的**推理方式**会再犯。
