# 提示词总表

> 写法参考网上公认的长时间自主运行做法：
> - Anthropic 官方的 Ralph 循环插件：结束条件是一句明确的"完成承诺"，进度写进文件，每一轮都从文件接着做（https://github.com/anthropics/claude-code/blob/main/plugins/ralph-wiggum/README.md）。
> - AFK 长任务实践：进度文件、明确的停止条件、每次只做下一件事（https://www.aihero.dev/tips-for-ai-coding-with-ralph-wiggum）。
> - 官方 Stop hook：在模型想结束时把它拦回去继续干（https://code.claude.com/docs/en/hooks-guide）。
>
> 默认只用下面两段提示词；第三节的 Ralph 循环是**可选**的加固手段。守护脚本 `守护_不间断运行.ps1` 和 `resume_prompt.txt` 保留但不再使用。

## 一、主提示词（睡前复制给 Claude Code，只发一次）

```text
你是晶圆项目 v5 的唯一执行方。用户在睡觉，09:00 起床，整夜没有人回答你的任何问题。

【唯一成功标准】
D:/pycode/晶圆图研究/协作/02_ClaudeCode_实操/v5_感知训练_20261012/E_结果/初版报告.md 已写好并 git commit，
且同目录 ALL_DONE.flag 已创建。

【唯一允许结束回复的条件】
上面的成功标准已经达成，或者当前时间已过 08:50。只有这两种情况才可以停止调用工具。
其他任何情况下结束回复都是错误：包括"完成了一个阶段""遇到报错""在等 GPU""需要用户确认""上下文很长"。

【开工步骤】
1. 完整读 D:/pycode/长鑫项目/学习计划_20261011/v5执行手册/00_总纲与合同.md（第 0 节优先级最高）。
2. 用 TodoWrite 建清单，至少包括：A 数据引擎、B 代码、C 上传与冒烟、D 启动夜跑、D 巡检、E 初版报告。
3. 按顺序执行同目录任务卡：A_数据引擎.md → B_代码.md → C_上传与冒烟.md → D_夜跑.md → E_结果分析.md。

【每做完一步，必须照做】
a. 更新 v5_感知训练_20261012/PROGRESS.md：已完成什么、下一步具体是什么；然后 git commit。
b. 更新 TodoWrite 清单。
c. 自问："清单里还有没完成的项吗？"有，就立刻开始下一项，不写总结、不停顿。

【遇到问题】
不提问，不等待。按总纲 0.4 降级决策表选默认方案，把时间、问题、选择、理由写进 DECISIONS.md，然后继续。
一个步骤反复失败 3 次：按决策表降级或跳过该项，标 not run，继续做下一项。不能因为一项失败就停下全部工作。

【等待 GPU 时】
不要结束回复。用 Bash 执行 sleep 540（单次不超过 9 分钟，避免工具超时），醒来后巡检服务器调度器状态
（按任务卡 D 第 5 步），把巡检结果追加到 PROGRESS.md，然后再 sleep，如此循环。08:30 后执行任务卡 E。

【禁止】
- 禁止以"要不要继续？""是否需要我……？""下一步建议"结尾。
- 禁止只写计划不执行。
- 禁止修改合同里的任何数值。

【红线】
不伪造（not run 不是 0）；不写"金标"；不写凭据和真实服务器地址；不抢卡、不杀他人进程；
CUDA_VISIBLE_DEVICES 在 Python 启动前设；上传后核对字节数；ssh 多条命令写进脚本文件再执行；
奖励函数单元测试必须先全过；起点 adapter 用 args.json 和张量门槛核验；先剥空 think 前缀再解析；
不挑 checkpoint；数据顺序与 seed 固定；GPU 训练只由服务器端 setsid nohup 调度器执行。

【时间表】
A 03:00 前，B 04:00 前，冒烟与夜跑启动 04:45 前，08:30 训练硬截止，08:45 前写完初版报告。
来不及就按总纲 0.3 先砍 P2、再砍 P1，P0 优先。

现在开始：读总纲，建 TodoWrite 清单，执行任务卡 A。
```

## 二、续跑提示词（会话意外断开、或上下文被清空后，开新会话发）

```text
你是晶圆项目 v5 的执行方，接着上一个会话继续。用户在睡觉，整夜没有人回答你的问题。

成功标准与唯一允许结束回复的条件不变：
E_结果/初版报告.md 已 commit 且 E_结果/ALL_DONE.flag 已创建，或者当前时间已过 08:50。其他情况一律不得结束回复。

步骤：
1. 读 D:/pycode/长鑫项目/学习计划_20261011/v5执行手册/00_总纲与合同.md 第 0 节和第 10 节。
2. 读 D:/pycode/晶圆图研究/协作/02_ClaudeCode_实操/v5_感知训练_20261012/PROGRESS.md 和 DECISIONS.md。
3. 用 TodoWrite 按 PROGRESS.md 重建清单；已打勾的步骤不要重做。
4. 如果服务器上的夜跑调度器已在运行（/WS/v5/night/scheduler.pid 存在且进程在），不要重复启动，
   直接进入巡检循环：sleep 540 → 巡检 → 追加 PROGRESS.md → 再 sleep；08:30 后执行任务卡 E。
5. 否则从 PROGRESS.md 记录的"下一步"继续执行。

每做完一步：更新 PROGRESS.md 并 commit → 更新清单 → 还有未完成项就立刻继续。
遇到问题按总纲 0.4 决策表处理，写进 DECISIONS.md，继续；同一步失败 3 次就降级或跳过，标 not run。
禁止以提问或"下一步建议"结尾。红线与主提示词相同。
```

## 三、可选加固：Ralph 循环（官方插件，基于 Stop hook）

作用：模型一想结束回复，Stop hook 就把同一段提示词重新发给它，直到它输出完成承诺 `<promise>V5_DONE</promise>`，或者达到最大轮数。进度靠 `PROGRESS.md` 接续，所以重复发送同一段提示词不会让它从头再做。

开法（在 Claude Code 里输入）：

```text
/plugin install ralph-loop@claude-plugins-official
/ralph-loop "先读 D:/pycode/长鑫项目/学习计划_20261011/v5执行手册/提示词总表.md 第二节（续跑提示词），然后严格照做。只有在 E_结果/初版报告.md 已 commit 且 ALL_DONE.flag 已创建，或当前时间已过 08:50 时，才输出 <promise>V5_DONE</promise>；否则绝不输出这句。" --max-iterations 200 --completion-promise "V5_DONE"
```

注意：
- 这是可选项。插件的 Stop hook 脚本依赖 bash、jq、perl。Windows 上如果没有 jq，插件可能不生效，这时只用第一节主提示词即可。
- 用 Ralph 循环时**不要**再单独发第一节主提示词，避免两套指令同时生效。
- 一定要设 `--max-iterations`。完成承诺是精确字符串匹配，只能有一个。
