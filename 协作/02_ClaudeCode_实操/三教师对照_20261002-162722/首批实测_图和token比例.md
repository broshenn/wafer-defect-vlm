## 1. 图和 token 的比例

### 1.1 图片本身占多少 token **[事实]**

**qwen 的响应直接给出了拆解**（不用反推）：

```json
"prompt_tokens_details": {"cached_tokens": 0, "image_tokens": 198, "text_tokens": 296}
```

| 项 | 值 |
|---|---|
| **一张 448×448 PNG 的图片 token** | **198**（qwen 直接报出） |
| deepseek 差值法估计 | ~185（497 − 312，**精度较低，见下**） |
| 提示词文本 token | 296（qwen 同响应）/ 312（deepseek 纯文本探针） |

**⚠️ 方法学提示**：我先用「带图 prompt − 纯文本 prompt」做差，得 qwen 图片 = 160；
但 qwen **自己报的是 198**。两者差 38 —— 说明**差值法不可靠**
（同一段文本在有无图像的上下文里，分词结果会变）。**以服务商直接给出的 `image_tokens` 为准。**
deepseek 的 usage 里没有图片拆分，只有 `prompt_cache_miss_tokens`，所以它那个 ~185 只能算估计。

### 1.2 比例 **[事实]**

| 比法 | 值 |
|---|---|
| 图片 token : 提示词文本 token | 198 : 296 ≈ **1 : 1.5** |
| 图片文件字节 : 图片 token | 1829 B : 198 ≈ **9.2 字节/token** |
| 图片 token : 本条请求总 token | 198 : 1552 ≈ **1 : 7.8** |

> **[解释]** 图像不是成本大头 —— **推理 token 才是**（见 §2）。

## 3. 100 万免费额度够跑多少张 **[事实+推算]**

| 口径 | 单次 | 100 万 token 可跑 |
|---|---|---|
| 按 qwen 实测 1552 | 1552 | **≈ 644 次** |
| 按 deepseek 实测 1997 | 1997 | **≈ 500 次** |
| 计划里百炼要跑 36 次（kimi 18 + qwen 18） | — | 约 **5.6%** 的额度 |

**[解释]** 余量约 **14–18 倍**。先前那个「最坏 697,824 token（70%）」的估计
按的是「每次输出用满 16384」，**实测输出只用了一千多**，所以那个估计**过于保守**。

**建议**：把守卫的 `INPUT_TOKENS_WORST` 从 3000 改成实测值，或把 max_tokens 从 16384 下调到
实测上限的 2–3 倍 —— 但这属于**改锁定参数**，按任务书要先写清理由，**本轮未改**。
