### 2.2 **两处实测缺陷**（在 `core_v3_复核修复.py` 修，**未改你的原件**）

**A. `parse()` 不认"完整空 think 包装"——这条不修，v3 奖励会恒为 0**

用 v3 **真实训练答案**做对照：

| 输入 | 你的 `parse` | 我的副本 |
|---|---|---|
| 裸 JSON（512 条） | 512/512 | 512/512 |
| **同上 + `<think></think>` 前缀** | **0/512** | **512/512** |

依据：起点修复轮 **360/360** 原答都带此前缀；而 **v2 的适配目标同样是裸 JSON**，
训出来的模型**仍然**带前缀 → 说明"用裸 JSON 训练"去不掉它。
若不修：每次 GRPO 生成解析失败 ⇒ 事实分 0、格式分 0 ⇒ **奖励恒 0，RL 无信号**。
处置：剥掉**完整空**包装（非空 think 不放过），**另留 `parse_raw_strict()`** 让"原始全文严格 JSON"
口径可单独统计——两个口径分开，不互相遮盖。

**B. "角向答 unknown 但扇区为空"白拿 0.4**

参考 `nondirectional` + `[]` 时，模型回 `unknown` + `[]`，扇区集合**恰好相等** → 白拿 0.4。
实测：**原件 reward 0.880 / 角向 0.4 → 复核版 reward 0.800 / 角向 0.0**。
处置：扇区分要求模型**确实给了方向类型**（非 unknown）才计入——「没回答不算答对」。

**我副本的自测：17/17**（重复键、非有限常量、bool 冒充扇区、字段集、字段间一致性、参考侧拒收等）。
**阈值、权重、字段名、题面一律未动**；WorkBuddy84 依赖的 hash 未受影响。

## 三、我这一轮犯的错（留痕）

1. **第一版复核脚本的空检查**：我用 `features.get('n_red', 0)` 统计红点数，
   但池里 `features` 用的是 **`defect_count`，没有 `n_red`** → 全部落到默认 0，
   得出"none 类红点>0 的有 0 个"这种**看似通过的空结论**。第二轮改成键名正确且**缺键即报错**才得到真结果。
2. **自测里的静默不匹配**：用字符串替换构造 `NaN` 用例，`json.dumps` 默认带空格导致替换没生效，
   测试"通过"了却什么都没测到。改成显式构造。
   → **两次同类错：检查写错了却显示通过。** 这也是我此后每条检查都写"缺键/无匹配即报错"的原因。
