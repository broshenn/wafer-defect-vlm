## 五、奖励解析器：**两处实测复现的缺陷**（已在副本修复）

副本：`core_v3_复核修复.py`（**不改** `core_v3.py`）。证据：`复核_两版解析器差异.json`。

### 缺陷 A：`parse()` 不认"完整空 think 包装" → 真实原答会 0 分

- 实测事实：起点修复轮 **360/360** 原答带 `<think>\n\n</think>\n\n` 前缀；
  而 **v2 的适配目标同样是裸 JSON**，训练出的模型**仍然**带前缀 ⇒ 用裸 JSON 训练去不掉它。
- 用 v3 真实训练答案做对照：

| 输入 | 原件 `parse` | 复核版 `parse` |
|---|---|---|
| 裸 JSON（512 条） | 512/512 | 512/512 |
| **同上 + 完整空 think 前缀** | **0/512** | **512/512** |

- **后果（若不修）**：v3 每次 GRPO 生成都解析失败 → 事实分 0、格式分 0 → **奖励恒为 0，RL 无信号**；
  评测也会显示"格式全灭"。
- 处置：剥掉**完整空**包装（非空 think 不放过），与 v2 冻结口径一致；
  **另保留 `parse_raw_strict()`**，让"原始全文严格 JSON"口径仍可单独统计——两个口径分开报。

### 缺陷 B：「角向答 unknown 但扇区为空」白拿 0.4

- 原件：`angular = .6*(类型对) + .4*(扇区集合相等)`。
  参考是 `nondirectional`（扇区为空）时，模型回 `unknown` + `[]`，**扇区集合恰好相等** → 白拿 0.4。
- 实测：参考 `Center/nondirectional/[]`，模型角向答 unknown →
  **原件 reward 0.880、角向分 0.4**；**复核版 reward 0.800、角向分 0.0**。
- 处置：扇区分要求模型**确实给了方向类型**（非 unknown）才计入 ——「没回答不算答对」，
  与 v2 已写明的契约一致。
