# 下一轮小测试合同（草案，**待 Codex 验收与正式运行放行**）

> 任务书第 3 项。**本件只是合同，不执行 GPU 段；方案预算不等于授权。**
> 依据：`训练组诊断.md`（训练侧归因）与 `mask检查报告.md`（掩码与起点检查）。

## 一、先说结论：**没有发现规则实现错误**

| 检查 | 结果 |
|---|---|
| 奖励是否把答对的判错 | **没有**：42 个未满分同分组里，五字段"有正确候选却未拿满"**全为 0** |
| 掩码是否接线错误 | **没有**：只有 assistant 答案段（含模板空 think 前缀与结束符）被监督；问题与图片不监督；无截断 |
| SFT 与 GRPO 的 token 监督是否不同 | **不是**：`default` 与 `last_round` 的监督位逐 token 一致 |
| 失败主因 | **模型系统性答错**：区带 31/42 组、覆盖 17/42 组**从未生成正确候选** |

→ 因此**不改评分尺、不放宽阈值、不硬造 M3**。

## 二、唯一候选改法：**按区带参考组合分层重采 RL 训练组**

**证据链**（全部来自本轮 CPU 归因）：

1. 28 个"四候选全同且都错"的区带答案里，**26 个都是 `['middle','edge']`**；
2. 而 RL 池的区带参考分布是 `['middle','edge']` **45.7%**、`['center','middle','edge']` 36.7%、
   `['edge']` **16.0%**、其余 1.6%；
3. 最干净的证据：9 组参考为 `['edge']` 的图，**middle 区带的红点质量是 0.0–7.5%（中位 4.7%）**，
   模型**仍然答 `['middle','edge']`** —— 它给一个几乎零质量的区带也写上了 "middle"；
4. 同一批 42 组的生成多样性只有 **1.31 种不同答案/组**（全池 2.15），**69% 的组四候选文本完全相同**。

→ 这是**向最高频组合塌缩**：在"每字段 0/1 分"的奖励下，
**总答多数组合的期望收益最高**，模型走了这条捷径。

**改法**：重采训练组，使区带参考的**组合分布更均衡**
（提高 `['edge']`、`['middle']`、`['center','edge']` 等稀有组合的占比），
**其余一切不动**（题面、规则、阈值、权重、起点、步数、seed）。

**它改变了什么**：改变的是**奖励信号教什么** —— 让"总答 middle+edge"不再是高期望策略；
**不改**任何判分口径。

**为什么值得小测**：这是本轮唯一有直接、可复现证据支持的改法；
成本低（只换数据组成，不增步数）；且**可与"继续 SFT"在同一批数据上做匹配对照**——
若塌缩被打破，M2 的区带错误应下降而 M1 不受影响（M1 学的是逐图监督，不吃组合分布）。

**明确不提出的两个改法（本轮证据不支持）**：

| 不提出 | 理由 |
|---|---|
| **G 从 4 提到 8** | 28/42 的区带失败是"**四候选答法完全相同且都错**"；再采 4 个大概率还是同一个错答案，**不是采样不够** |
| **动态采样/换算法** | 任务书明令不因多数组同分自动启用；且本轮证据显示失败是"一起错"而非"都没梯度" |

## 三、合同条款

| 条款 | 内容 |
|---|---|
| **共同起点** | **现有 `M0_v3`**（adapter SHA `191c62e8…`），**不重训**；两线都用 `adapters=[M0_v3]`、`resume_only_model=True`，M2 另用 `ref_adapters=[M0_v3]` |
| **唯一主要变量** | **训练组的区带参考组合分布**（分层重采）。题面/规则/阈值/权重/步数/seed 全部冻结不动 |
| **数据** | 只从**原 train 侧**重采：`rl` 池 256 图基线不变，仅调整**进入 256 步训练序列的**组合占比；不与 adapt/rule_dev/confirmation 交叠。**不使用确认池 120 图做任何选择** |
| **题面/规则** | `题面_v3.txt` SHA `08533309…`；奖励用 `core_v3_复核修复.py`（与上轮同一份，阈值权重未动） |
| **seed** | 3407（`seed` 与 `data_seed`） |
| **对照** | M1b = 同一批 256 组上的**匹配继续 SFT**（每图 4 行、GA4、256 步）；M2b = 同一批上的固定规则 GRPO（G=4、T=1.0、top_p=1.0、β=0.04、256 步）。**两线同数据、同步数、同起点** |
| **主要指标** | 公开类别 Macro-F1（**按 lot 配对**，与 Codex 核对口径一致）；次指标为规则奖励（分列，不互相替换） |
| **分项** | 覆盖档位、径向区带、方向（三分母）、格式两口径；**区带按组合分别报**（重点看 `['edge']` 类是否还答 middle） |
| **门槛（开跑前必须过）** | ① 两线各自 `runtime_gate`：初始 policy（M2 加 reference）496/496 等于 M0_v3、参考两步后未变、非零梯度；② mask 检查复跑（本报告同款，确认监督位不变）；③ 单卡断言 `device_count==1`、`world_size==1` |
| **最大步数** | 两线各 **256 步**（每步 1 图组；256 组恰好 1 epoch，不重复 3 个 epoch） |
| **停止条件** | 2 步门槛不过 → 停；到 256 步即停；**不选"最好 checkpoint"**，固定末步 |
| **设备分钟估算** | 按本轮同机实测步速：SFT 5.04 s/step、GRPO 9.34 s/step、评测 120 图 ≈5.2 min/模型（含加载）。**M1b 256 步 ≈21.5 + M2b 256 步 ≈39.9 + 评测 3×120（含 M0_v3 复测）≈15.5 + 门槛 ≈2 → 合计 ≈79 设备分钟** |
