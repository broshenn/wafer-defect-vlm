## 一、简历项目段落（可直接复制）

### 版本 A：偏工程与流程（约 180 字）

> **晶圆 BIN 图多模态缺陷理解（Qwen3.5-9B）**
> 基于公开 WM811K/LSWMD 数据集（5,904 张晶圆图，9 类缺陷），搭建「数据 → 标注 → SFT → 类别奖励后训练 → 评测」全流程。
> 负责实验设计与验收：定义数据隔离规则（按 lot 分组、防跨划分泄漏）、
> 制定评测协议（严格 JSON 解析、九类固定 Macro-F1、配对比较）。
> 用 1,440 张训练集把开发集（84 张）准确率从未微调基座的 **20.2% 提升到 85.7%**；
> 在其上做 90 步类别奖励 GRPO，开发集达到 **89.3%**，高于同起点同预算的继续 SFT（86.9%）。

---

### 版本 B：偏研究问题（约 220 字）

> **从冷启动到类别奖励后训练：晶圆缺陷分类的可复现实验链**
> 在公开晶圆 BIN 图数据上研究「少量可靠示例 + 可核对判据能否减少对教师描述的依赖」。
> 完成：按 lot 隔离的训练/开发/确认集划分；教师模型小样本盲测选型；
> 冻结视觉侧的语言侧 LoRA SFT；以及**只奖励类别答对**的确定性奖励 GRPO。
> 关键结果：训练集从 180 → 1,440 张，开发集准确率 **76.2% → 85.7%**（未微调基座 20.2%）；
> 在 1,440 起点上做 90 步类别奖励 GRPO，开发集 **89.3%**，比匹配的继续 SFT（86.9%）高 2 条样本。
> 同时记录了负面结果：20 步小规模 GRPO **没有**超过起点，说明该量级下继续训练会轻微损伤模型。

## 三、3 分钟讲述稿

**（0:00–0:30）问题**

「我的项目是晶圆 BIN 图的缺陷理解。数据是公开的 WM811K，5,904 张图，九类缺陷，
每张图就是一格一格的 die，绿的合格、红的失效。
我要回答的问题不是「能不能训一个分类器」，而是**少量可靠示例能不能让模型学会基本判读**，
以及**把判读条件写成可核对的规则，能不能减少对教师模型描述的依赖**。」

**（0:30–1:15）做了什么**

「整条链路我做了四段：数据隔离、盲标注、监督微调、类别奖励后训练。
数据隔离我特别在意——按 **lot** 分组，任何一个 lot 只能出现在一个划分里，
因为同一批次晶圆的图长得几乎一样，混进去就等于泄漏。
标注走的是**无答案盲清单**，标注的人看不到类别、lot、几何信息。
监督微调是在 Qwen3.5-9B 上做**冻结视觉侧**的 LoRA，只训语言侧。」

**（1:15–2:15）结果**

「最关键的一组数字：**未微调的基座在开发集上只有 20.2%**——
它基本只会往一个类上猜。
**1,440 张训练集训一轮，开发集到 85.7%**。
这条规模曲线我跑了 180、360、720、1,440 四档，**每档都跑满 1 个 epoch**，
三种子极差只有 **1.19 个百分点**——种子波动很小。
不过我要说清楚：**这条曲线同时增加了数据量和样本呈现次数**，
所以是「充分覆盖条件下的规模曲线」，**不能单独归因到数据量**。」

**（2:15–2:50）奖励后训练**

「在这 1,440 的模型上，我又做了一组对照：
同一个起点，**一条继续做监督微调，一条做类别奖励的 GRPO**，
奖励函数只有一条规则——**类别答对得 1，其余得 0**，不用任何 LLM 打分。
两组都跑 90 步、都让 90 张图各过一次。
结果 **GRPO 89.3%，继续 SFT 86.9%**。
不过这个差距只有 2 张图，**在 84 条的样本量下大约是 1 个标准误，不能说统计显著**。」

**（2:50–3:00）收尾**

「另外我保留了负面结果：更早做过一组 20 步的小规模 GRPO，
**它没有超过不训练的起点**。我把这个也写进报告了——
小量级的继续训练会轻微损伤模型，这个信息比只报好的结果有用。」

## 四、可以讲的「坑」（面试时很加分）

1. **一个会静默失效的冻结开关。**
   ms-swift 里 `target_modules` 传**字符串** `"all-linear"` 时，
   代码第一行就 `return`，`freeze_vit` / `freeze_aligner` **根本不会被读取**，
   LoRA 会被插进视觉编码器——**而配置看起来完全正常**。
   实测差别：字符串 → 视觉侧 220/553 个张量可训练；列表 → 0/333。
   我是在「参数名字存在不等于实际冻结」这条要求下查出来的，改成显式列表并加了失败即停的自检。

2. **设备隔离写在 `import torch` 之后等于没写。**
   上一轮的脚本在 import 之后设 `CUDA_VISIBLE_DEVICES`，结果模型被 `device_map: auto`
   铺满了六张卡——**其中一张还是别人的**。日志里明明白白写着「可见 GPU 6」，
   但我当时没看。改成父进程设置 + 脚本内断言。

3. **对照实验的「呈现」必须核到实际序列，不能看文件顺序。**
   有一轮我以为两组用的是同一批图、同一个顺序，实际：
   图集只重叠 8/20（而且一组只有两类），
   两层打乱又开着，**20 个优化步里 0 步的 4 份样本来自同一张图**。
   修正后 RL 的优势从 +4 缩到 +1。**没核到实际序列就报「公平对照」是错的。**

4. **「没运行」不等于「零分」。**
   缺金标不是满分，未运行不是零分。所有没做的事我都单列成 not run。

## 五、边界（主动说出来，别等人问）

- 这是**开发集**上的点估计，不是正式泛化；最终测试集与冻结 Benchmark 没动。
- **形态、位置、尺寸**的判读**没有训练也没有评测**，本项目目前只做到**类别**。
- **没有任何人工审核环节**——所有数字都是程序按固定规则算的。
- **九类独立最终考卷目前凑不出来**：排除已接触样本后，
  Near_full 在验证集和测试集里都剩 0 条。
- 奖励池里 90 张图对起点模型已经偏容易（平均奖励 0.775），
  **90 组里有 64 组四个回答同分**，这些组不产生类别学习信号。
