## 1. 固定共同起点与同图呈现

### 1.1 R0 的构造

- **来源**：L1440 seed3407 **最终 checkpoint-360**（依据 `扩容主训练_20261006/训练配置_t1_1440_s3407.json`），
  **不按最佳开发成绩换其它 checkpoint**。
- **方法**：纯 CPU 合并（`merge_f0_cpu.py`，`device_map={"":"cpu"}` + `merge_and_unload` + safetensors），
  **0 GPU 分钟**；**原基座与 Adapter 均未覆盖**。
- 显式 `model_type`/`template_type = qwen3_5`，避免被误加载成文本模型。
- **合并忠实性**：R0 在 dev18 上 **15/18、MacroF1 0.829633**，
  与 L1440 Adapter 的成绩**完全相同**（`R0_dev18.jsonl` 与 `t1_1440_s3407_dev18.jsonl` SHA256 一致）。
  **未把原 72/84 当合并起点成绩，也未把舍入猜测当证实** —— 合并是单独评测的。

### 1.2 奖励池与共同顺序

- 奖励池 `rl_pool90` SHA256 `0569a20b…`
  **与冻结值逐字节一致**；**与新 1440 的 lot 交集 0、ID 交集 0**。
- 共同顺序：seed 3407，**九类交错**（前 9 条正好是九个类各一条），
  `固定顺序90.jsonl` SHA256 `7f084d15…`。
- **生成 prompt 不含 assistant 答案、不含 gold、不含 sample_id**。
- **R2 实际顺序核对**：`实际顺序 == 固定 order90` → **True**（从 reward audit 的 90 组 ID 逐条比对）。

### 1.3 两条路线的呈现计划

| | R2（GRPO） | R1（继续 SFT） |
|---|---|---|
| 每优化步 | 1 张唯一图 × G=4 | 4 行同图（正确答案连续 4 行） |
| 步数 | 90 | 90 |
| 全池覆盖 | 90 图各一次 | 90 图各一次 |
| 打乱 | **关闭两层** | **关闭两层** |

**实测**：R2 审计 90 组、组内同 ID（True）、唯一图 90；
R1 数据「每 4 行同图」为 True。**旧 F1 的「文件连续所以实际连续」错误没有重现** ——
本轮显式关闭 `dataset_shuffle` 与 `train_dataloader_shuffle`，并从审计反查实际顺序。

### 1.4 配置

两条路线都从**同一 R0** 新建同初始化 LoRA；参考策略也是 R0。

保留已验证：语言侧 `target_modules=["all-linear"]`（**列表**）、BF16、
LoRA 16/32/dropout 0.05、image token 256、max_length 2048、gradient_checkpointing、
seed=data_seed=3407、LR 1e-5、cosine、warmup 0。原分类题面与严格解析不变。

R2：`num_generations=4`、`temperature=1`、`top_p=1`、`max_completion_length=64`、
`beta=0.04`、`epsilon=0.2`、token 重要性采样、`num_iterations=1`、`use_vllm=False`。
**复用已验收的 reward_v1，未改奖励与 schema，未使用 LLM 评分。**

## 3. 解释与边界（重要）

- **R2 > R1 > R0 的差距是 2 条与 4 条（84 条上）**。
  84 条样本准确率的二项标准误约 **0.05**，**4 条的差距约 0.048** ——
  **接近但未超出 1 个标准误，不能宣称统计显著**。这是**开发集上的点估计**。
- **Near_full 在 val84 里只有 4 条**，该类结论**不外推**。
- 本轮只做 **seed 3407 一组**，未加种子、未扫超参、未因结果加轮次。
- **未做人审；未评正式 Benchmark；形态/位置/尺寸未训练也未评测。**
