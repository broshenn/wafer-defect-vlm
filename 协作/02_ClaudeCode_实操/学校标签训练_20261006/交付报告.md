### 1.4 发现并绕开一个会让冻结静默失效的坑 **[本次最重要的技术发现]**

任务书要求「核实 LoRA 可训练对象，ViT/aligner 冻结；**参数名字存在不等于实际冻结**」。照做之后发现：

`swift/utils/transformers_utils.py::get_target_modules()` 的**第一行**：

```python
if isinstance(args.target_modules, str):
    return args.target_modules      # ← 字符串直接返回，freeze_vit/freeze_aligner 根本不被读取
```

只有 `target_modules` 是**列表**时才继续走 `get_multimodal_target_regex(freeze_llm=…, freeze_vit=…, freeze_aligner=…)`。

**实测对照**（同样的 `freeze_vit=True, freeze_aligner=True`）：

| `target_modules` 写法 | 可训练参数 | 可训练张量 | 视觉侧可训练 |
|---|---|---|---|
| 字符串 `"all-linear"` | 51.265 M | 716 | **220 / 553 ❌ 未冻结** |
| 列表 `["all-linear"]` | 43.278 M | 496 | **0 / 333 ✅ 已冻结** |

即：**`--target_modules all-linear` 若被解析成字符串，冻结会静默失效，LoRA 会被插进 ViT，而配置里 `freeze_vit=True` 看起来一切正常。**

所以本次训练驱动脚本显式传列表，并在**训练前做失败即停的自检**（视觉侧可训练张量不为 0 就拒绝训练），训练后从 checkpoint 的 `adapter_config.json` 再核一次。

**持久证据**（`LoRA目标正则_adapter_config.json`，来自 checkpoint-60）：

```
target_modules = "^(model\.language_model(?=\.).*\.(o_proj|k_proj|q_proj|in_proj_b|down_proj|
                   out_proj|v_proj|in_proj_qkv|in_proj_a|in_proj_z|up_proj|gate_proj))$"
r=16  lora_alpha=32  lora_dropout=0.05
```

正则里**只有 `model.language_model.*`，没有 visual/vision**。
