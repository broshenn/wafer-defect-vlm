## 0. 先说清楚一条边界：原始矩阵不在本地

**[事实]** `data/raw/` **本机不存在**（`AGENTS.md` §15 已写明本地没有 `raw`）。因此**无法**按任务书 §1 说的
"若本地能取得原始矩阵，按历史固定渲染函数独立比对" —— 原始 pkl 拿不到。

**[事实]** 但我找到了另一条路，而且它**不依赖原始数据**：

历史渲染函数 `matrix_to_image`（`code/projects/wafer-defect-vlm/src/wafer_vlm/utils.py:231-236`）是

```python
Image.fromarray(rgb).resize((448, 448), Image.Resampling.NEAREST)
```

**NEAREST 放大是纯复制**，不插值、不混合。所以目标像素 x 与源列的关系是 `src = floor(x·W/448)`，
**逐列一一对应、可逆**。于是可以从 PNG **逐格反解**出原矩阵。

**无损性不是推的，是证的** —— 往返检验：把反解出的矩阵用**同一个历史函数**重新渲染，
与磁盘上的原 PNG 逐**像素**比对。

| 九张结果 | 反解 (H,W) vs manifest `matrix_shape` | 重渲染像素差 |
|---|---|---|
| **9/9 一致** | 全部相符 | **全部为 0** |

**[事实]** 另一条独立佐证：用"颜色边界落在周期格点上"做**格点拟合**，另外 20 张随机样本
**20/20** 与 manifest 的 `matrix_shape` 相符，拟合得分全部 1.000。

> **本报告此后一律称"反解矩阵"，不冒充原始数据复验。**
> 字节级说明：重渲染的 PNG **字节**与原文件不同（IDAT 长度 1597 vs 1666）。
> 实测 `optimize=True`/默认/`compress_level=6`/`9` 都得不到原字节 —— **[解释]** 原图是服务器上
> 另一个 PIL/zlib 版本写的。像素相同、字节不同，所以无损性证明只能做到像素级。

### ⚠️ 本轮最重要的方法学发现：**矩阵 shape 无法从图上"看"出来**

**[事实]** 实测 300 张样本（涵盖 **81 种**矩阵形状，边长 22 到 150）：**非黑区域在横向与纵向都铺满 448 px，300/300**。
无论原矩阵是 22×22、56×41 还是 150×150，渲染出来都是**同一个满幅的圆**。

**[解释]** 这**不是 bug**。die 是矩形的，圆片在矩形 die 栅格里的边界本来就是**椭圆**；
`resize` 的不等比拉伸正好把这个椭圆还原成正圆。渲染在几何上是**正确且必要**的。

**[事实]** 但它有两个后果，都写进了 `踩雷记录` **B36**：

1. 图上没有任何分辨率信息 —— 想要核对 `matrix_shape`，只能像我这样反解或做格点拟合；
2. **`AGENTS.md` §7.1 要求的「不同矩阵尺寸」鲁棒性维度，在当前渲染下根本测不到** ——
   所有尺寸看起来完全一样，模型不可能因为矩阵大小而答对或答错。这条维度实际是空的。

## 2. 特征复算：与 manifest 自带的 `features` 对照

**[事实]** 用**历史同一个** `calculate_static_features` 在反解矩阵上复算，与 manifest 存的值逐字段比对：

| 样本 | 最大相对差 | 结论 |
|---|---|---|
| item_001 / item_003 / item_004 / item_005 / item_007 / item_008 / item_009 | **8.8e-16 ~ 8.5e-15** | 逐字段吻合 |
| item_002、item_006 | **1.05e-01 / 5.00e-01** | 仅 `angular_probability` 与 `angle_entropy_bits` 两个字段不同 |

**[事实] 那两张的差异不是算错，是扇区边界上的不确定性**：

- `wafer_00043922_015` 的 482 个缺陷里，**25 个（5.2%）到扇区边界的角距恰好是 0.0**；
- `wafer_00013704_014` 的 94 个里有 4 个角距 `4.65e-16`。

`np.histogram` 用半开区间，圆心只要差 1e-15，这些边界点就翻到相邻 bin —— 于是这两个字段变了。
**[解释]** 轴对齐的缺陷（正上/正右/正下方）天然落界，所以这不是偶发。已记入 `踩雷记录` **B37**。

> **意义**：`angular_probability` 与 `angle_entropy_bits` **不是可复现的确定性量**，
> 不适合当打分或验收的 gold。其余所有字段（类别、径向、计数、质心、跨度）**吻合约 1e-15**。

## 4. 问 3：标签定义证据 —— **公开定义是定性的，没有可用的数值阈值**

**[事实]** 仓库里**没有**任何带阈值的类别定义。能找到的只有注解：`docs/LIMITATIONS.md:778-780`
写 `Random`（随机散布）、`Donut`（环）、`Edge_Loc`（边缘局部）。`docs/WaferSAGE_中文精读与训练方案.md:130`
提到 Scratch 应说明"线状缺陷是否从边缘延伸到中半径区域"，但那是**笔记**，不是引用。

**[事实]** 查公开来源（WM-811K，TSMC/MIR 发布，人工标注），八个类别的定义是**定性描述**：

| 类 | 公开定义 |
|---|---|
| **Loc** | 局部失效簇；**与 Edge-Loc、Center 几何相似，只靠位置区分** —— 簇既不在中心也不在边缘 |
| **Edge-Loc** | 缺陷簇位于**晶圆边缘区域**，**与角度位置无关** |
| **Donut** | 环状失效图案，**中心留空**，形似甜甜圈 |
| **Random** | **逐点随机分布**的失效，缺陷一般不聚集在特定区域，而是遍布整片 |
| **Scratch** | **线状划痕**，任意长度、任意区域，形似刮痕 |
| **Near-Full** | 几乎所有 die 失效，图案覆盖几乎整片晶圆 |
| **none** | **只有随机缺陷、没有明显图案**；其余标签表示"在随机缺陷之外**还有**系统性缺陷" |

**[事实]** 专门查了 Loc / Edge-Loc 的边界：**没有任何公认的数值径向阈值**。
标签由**人工专家**判定，判据是"边缘区 / 中间区"这种定性位置描述。
能找到的最接近的量化参数出在一篇特征工程论文里（edge zone = `10 < radius ≤ 14`、center zone = `radius ≤ 8`），
但那是**那篇论文自己选的工程参数，不是 WM-811K 的标注规则**。

> ### **所以：没有正式阈值，判据是缺失的。**
> 本报告**不**由这四张倒推通用阈值，**不**假称资深工程师规则。
> 下面用的"密度分位"是把该样本放到**整个训练集该类分布**里的位置 —— 那是**背景参照，不是判据**。

**[事实] 作为背景**（`data/manifest.jsonl` 训练集，`defect_ratio` 分布）：

| 类 | n | 中位 | 10–90 分位 |
|---|---|---|---|
| `none` | 337 | 5.8% | 1.3% – 13.7% |
| `Scratch` | 653 | 5.6% | 1.4% – 15.5% |
| `Loc` | 622 | 9.4% | 1.5% – 21.6% |
| `Edge_Loc` | 637 | 11.4% | 4.5% – 28.8% |
| `Donut` | 428 | 23.4% | 13.7% – 43.9% |
| `Random` | 634 | **46.9%** | 30.9% – 61.9% |

**[解释]** 这张表说明两件事：`Random` 与 `none`/`Scratch` 在密度上**差一个数量级**（46.9% vs 5.6–5.8%）；
而 `Loc`/`Edge_Loc`/`Donut` 三者**区间大幅重叠**，密度**不能**用来区分它们。

## 5. 问 4：每张三层的结论

> 任务书要求"只能支持样本对应、标签边界或结构误读哪一种，就写到哪一种"。
> **四张的"样本对应"都成立，且分歧没有一张是"视觉幻觉"** —— 证据如下。

### item_001 · none → Random

- **[事实]** 全片只有零星孤立红点：37.9% 的失效是孤立单格，最大连通块仅 6 格，无环、无条带（条带性 0.290 不显著）。
  密度 7.29%，在 `none` 人群第 61.7 分位，在 `Random` 人群第 **0.0** 分位。
- **[解释]** 模型的**形态描述与实测完全一致**（"孤立散点状遍布整个晶圆，未见成片簇、环状或条带结构"）。
  分歧**不在看到了什么，而在把这种形态叫什么**：公开定义里 `none` = "只有随机缺陷、没有明显图案"，
  而 `Random` 是**明显以随机缺陷为图案**的类。7.29% 的密度落在 `none` 的中位区，且低于**每一张** Random 样本。
- **[未测]** `none` / `Random` 的边界**没有公开数值判据**。当年标注者认为"多少散点才算图案"无法复算。
- **支持哪一种：标签边界。** 不是结构误读 —— 模型的描述准确，但类别命名与数据集密度分布不符。

### item_003 · Loc → Edge_Loc

- **[事实]** 44 格致密簇**紧贴晶圆左下边缘**（到边界距离 0 格，最近边界格 [47, 4]），
  其余 40.2% 的失效是散布全片的孤立点。密度 2.52%，在两类人群里都很低（17.7 / 3.1 分位），**密度不区分**。
- **[解释]** 公开定义里 **Edge-Loc = 簇在边缘区域（与角度无关）；Loc = 簇既不在中心也不在边缘**，
  **只靠位置区分**。本图的簇**在边缘上**，位置判据支持 `Edge_Loc`。
  另：历史 `radial_zone` 由**全体缺陷质心**得出（r=0.150 → 会判 `center`），
  但 40% 的散点把质心拉向了中心 —— **这正是"不以旧质心 radial_zone 单独证明位置"的实例**。
- **[未测]** 边缘/中间的分界**没有数值阈值**。簇贴边到什么程度算 Edge-Loc，公开定义没说。
- **支持哪一种：标签边界。** 且证据**偏向 Edge_Loc 一侧**（位置判据明确），但不构成对原标签的否定。

### item_007 · Donut → Loc

- **[事实]** 径向剖面是**教科书式的甜甜圈**：中心 r<0.1 只有 2.4% 失效（41 格里 1 格），
  密度单调升到 **41.3% @ r=0.4–0.5**，再回落到 5.1%。主簇离边缘 12 格，不接边。
- **[解释]** 公开定义里 **Donut = 环状、中心留空**。本图的中心**就是空的**，密度峰在中径。
  模型说的 `Loc` 意味着一个紧凑局部块，而剖面显示的是**环**，不是一个块。
- **[未测] ⚠️ 两个判据在这里互相矛盾**：按**形状**，证据支持 Donut；按**密度**（12.67%），
  它在 `Donut` 的第 7.5 分位（低于其 10 分位）、却在 `Loc` 的第 62.7 分位（舒适区）。
  **公开定义没有说形状和密度谁优先。**
- **支持哪一种：标签边界。** 但必须并列报告两个判据冲突，**不下单一结论**。

### item_008 · Random → Scratch

- **[事实]** 全片 43.85% 失效，最大连通块占全部失效的 **71.4%**，几乎无散点（2.7%）。
  逐列失效率在**周期 3 处自相关 0.745**；零模型（同密度同掩膜随机置换 300 次）**最大只有 0.472**，
  观测值超过全部随机抽取。对照样本均不显著。
- **[解释]** 模型说的"多条近竖直红色条带纵贯晶圆上下"**是真结构，不是幻觉** ——
  在这个密度下随机撒点**做不出**这么强的列向周期性。所以这**不是结构误读**。
  但 `Scratch` 的公开定义是"**线状**划痕"，而本数据集 `Scratch` 类中位密度 5.6%、90 分位 15.5%；
  本图 43.85% 是**每一张 Scratch 都达不到的密度**（第 100 分位）。一条"细线"覆盖不了近一半的 die。
- **[未测]** `Scratch` 的定义**没有密度条款**，所以不能从定义上排除它；
  也无法判断这个条纹来自原始 wafer map 还是上游数据处理的产物（我只能看到 die 栅格）。

  但"这个真结构该不该叫 Scratch"，公开定义答不了。
