## 四、判据与阈值从哪来（**不来自 36/56 测试集**）

| 量 | 值 | 依据 |
|---|---|---|
| 覆盖档位边界 | 5% / 20% / 50% | train 侧全量分布（中位 18%、P95 60%） |
| 区带质量阈值 | ≥10% 且 ≥2 个红格 | 避免单格噪声；红格 <3 全记 unknown |
| 方向 R1/R2 阈值 | 0.60 / 0.70；无方向 0.20/0.30 | train 侧逐类分位：环状/全局类的 R1 p99 ≤ 0.38，单向下限取在其外 |
| 轮廓异常阈值 | 10% | 实测 leak 最大 4.5%、hole 最大 17.9%（5904 张），阈值只捕捉严重非椭圆 |
| 扇区并列容差 | ±3° | 定义，非拟合 |

**36 图 / 56 图只作开发诊断，未参与阈值选择**；v2 的留出卷是新冻结的 `确认池`（120 图）。

## 四点五、**最重要的一处更正（先读这条再看数字）**

初版报告写"M1/M2 从共同起点 M0 继续训练"—— **这是错的**。
`--start-adapter` 的 `**extra` **从未传进构造函数**，训练器自存的 `args.json` 显示
M1/M2 的 `adapters=[]`。三条线实际都是**合并基座上的独立 LoRA**：

- **M1 vs M2 仍是干净的匹配对照**（同基座/同 60 图/同顺序/同步数，只差 SFT vs GRPO）；
- **M0 与它们不同线**，它更高只能读成"256 图适配这条线更好"，
  不能读成"继续训练导致退化"。
- 详见 `out_v2/更正_v2/更正说明.md` 与 `实跑件证据.json`。

## 五、边界（不能说的）

- 首轮**不是**独立九类最终考卷（确认池缺 `Near_full`，且与旧数据同源同分布）。
- **方向字段覆盖很窄**：全量 5904 张里坐标合格的方向只有 1.5%（`single` 62 + `axis` 27），
  确认池 120 图里只有 5 张。方向结论只能按这 5 张报，且必须写清。
- 训练目标里的 `caption_zh` 是**程序模板**（由类别/区带/覆盖/方向拼出），
  只用于让模型学会该字段的位置，**不用来评价描述能力**。
- 真人复核仍为空白（用户已定永久不做）；AI 复核不是人工 gold。
- 本轮 GPU 全部在**用户自行租用的实例**上跑，不涉及学校机器；租机人民币账单仍未知。
