### 〇、必须先讲的错：**M1/M2 实际没有从 M0 继续训练**

你在第 4 条里提醒"496 个相同张量名称 + 训练后差异只是辅助证据，不能说新 adapter 必然接近 100%"。
**你是对的，而且事情比这更严重** —— 我顺着这条查下去，发现：

- 我给脚本加 `--start-adapter` 时，**定义了** `extra = {"adapters": [...], "resume_only_model": True}`，
  **却从未把它传进 `SftArguments` / `RLHFArguments` 的构造函数**（`**extra` 没插进去）。
- **决定性证据**：checkpoint 里**训练器自存**的 `args.json` 显示 M1/M2 的
  **`adapters=[]`、`resume_only_model=False`**（M0 也是 `[]`/`False`）。
  远端脚本 SHA 与仓库副本逐字节相同，所以不是"传错了文件"。
- **后果**：M1 与 M2 都是在合并基座上训练的**全新 LoRA**，不是 M0 的续训。
  脚本仍然打印了"从已有 adapter 继续：…"并记下它的 SHA —— **打印的是意图，不是实参**；
  我写的 `v2_config.json` 里 `start_adapter` 字段因此是**错误记录**。
- **更正后的设计**：
  - M0 = 合并基座 + 全新 LoRA，256 图 schema 适配，64 步；
  - M1 = 合并基座 + 全新 LoRA，60 图 SFT，60 步；
  - M2 = 合并基座 + 全新 LoRA，60 图 GRPO，60 步。
  - **M1 与 M2 仍是一对干净的匹配对照**（同基座/同 60 图/同顺序/同步数，只差 SFT vs GRPO）—— 这一对是有效的。
  - **M0 与它们不是同一条线**；M0 更高只能读成"256 图适配这条线更好"，
    **不能**读成"继续训练导致退化"，更不能读成"RL 把能力练坏了"。
- 证据固化：`out_v2/更正_v2/实跑件证据.json`（脚本与数据 SHA、各 checkpoint 实参、三个 adapter 权重 SHA）。
  远端脚本、`args.json` 原件存 `out_v2/服务器产物/远端实跑件/`。

**修正你第 4 条的一处前提**：22:25 那次"补 `**extra`"只补到了**变量定义**，没补到调用点。
