## 六、服务行为（**如实列**）

1. **真实推理，不读预存答案**：每条请求都过模型；`runtime_records/<request_id>.json`
   逐条留档，含模型 tag、adapter 哈希、图片哈希、题面哈希、原始输出、格式改动、耗时、显存、失败原因。
2. **只允许一种展示级规范化**：`clock_direction` 的字符串 `"null"` → JSON `null`，
   且**原答保留在 `raw_answer`**，改动记在 `format_changes`。
   **不把修后算作原模型的格式成绩。**
3. **非法字段不推断补造**：schema 不通过的，`result` 置空并标 `needs_review`。
4. **`needs_review` 只提示、不当结论**：它覆盖格式问题、模型自报的不确定项、
   以及形如「约 3%-4%」「0.1R」的**未核数量/尺寸表述**。
   服务代码里写明：**`needs_review` 不是经校准的置信度，也不是全部错误检测器**。
5. **方位不适用时可以为空**，不强迫每图都有钟点方向。

## 七、**这个原型能做什么、不能做什么**

**能**：接受**项目渲染器生成的 448×448 黑/绿/红三色 PNG**，返回七字段结构化判读；
对超尺寸、损坏、非三色图给出明确拒绝；串行稳定，单请求约 4–5 秒。

**不能 / 未验证**：
- **不宣称为任意产线图可直接接受** —— 只验证了本项目的渲染格式；
- **HTTP 200 不等于内容正确**；描述事实要另做逐图自查（见 `描述自查与对照.md`）；
- **不是经校准的置信度系统**；
- 未做并发压测（单 GPU **串行**，同时请求会返回 429「模型忙」）；
- 未接入厂内系统、未发布公网。

## 八、启动与关闭

启动（`/WS/deploy/`）：
```bash
export CUDA_VISIBLE_DEVICES=<本人获准卡的UUID>
export IMAGE_MAX_TOKEN_NUM=256 PYTHONNOUSERSITE=1
export WAFER_CHECKER=/WS/deploy/schema_check.py
python /WS/deploy/test_cpu_contract.py                       # 6 项 CPU 契约
python /WS/deploy/wafer_service.py \
  --model /WS/models/Qwen3.5-9B --adapter /WS/adapters/D-N3072-3407 \
  --tag D-N3072-3407 --prompt /WS/deploy/prompt_7f.txt \
  --checker /WS/deploy/schema_check.py --out /WS/deploy/runtime_records \
  --host 127.0.0.1 --port 7860 --max-runtime-seconds 2700
```

关闭：`--max-runtime-seconds` 到点自动 `os._exit(7)`；
也可手工 `pkill -f wafer_service.py`。
**进程退出不等于平台已关机 —— 计费状态仍以平台控制台为准。**

复跑自测：
```bash
python /WS/deploy/replay_selftest.py --url http://127.0.0.1:7860 \
  --samples /WS/deploy/样本清单.json --images /WS/deploy/图 --out /WS/deploy/selftest
```

（脚本**拒绝覆盖已有结果**，重复回放需换 `--out`。）
