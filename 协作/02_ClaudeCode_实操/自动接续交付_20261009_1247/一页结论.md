# 一页结论（2026-10-09）

**项目**：用公开数据（WM811K）研究「晶圆 BIN 图缺陷判读 + 中文描述」的视觉语言模型，
并把判读能力落成一个可审计的 HTTP 服务。

**资源**：百炼 API 实付 **≈4.90 / 20 元**；训练用公开数据 **3072** 张；对照集固定 **36** 张（开发集）。

---

## 我做了什么

1. **训练了两个同基座模型**（Qwen3.5-9B，同 3072 图、同题面，**只改监督答案**）：
   `L` 只给类别，`D` 给类别 + 形态 + 中文描述。
2. **建了固定 36 图、八模型的同题对照**：本项目两个模型 + 原生基座 +
   四个百炼 API 模型（`qwen3.8-max-0902`、`qwen3.5-397b-a17b`、`qwen3-vl-plus`、`kimi-k3`）+ 外部 GLM。
3. **把描述事实评法从自由文本正则改成冻结枚举**（六维 + 方向两列，回归 20/20 才开工）。
4. **部署了一个真实 HTTP 服务**并做了 36 图真实回放 + CPU 契约测试。

## 三个数字

| | |
|---|---|
| **0.1667 → 0.8889** | 同基座、同题面、同参数，**只把监督从「无」换成类别标签**（36 图） |

| **25 / 36** | 部署服务在 36 图上实际 HTTP 判对的条数（Macro-F1 0.6756，p95 4.9–5.4 s，36/36 HTTP 200） |

---

## ✅ 支持

- 公开标签监督能**大幅**提升 9 类判读：Base 0.1667 → L 0.8889；旧 84 图上 77/84（91.7%）。
- 冻结枚举能把**格式失败**与**内容错误**分开（397B 严格 0 → 围栏诊断 22.2%）。
- 能力**能落成服务**：原答逐字节保留、坏结构不修补、CPU 契约 6/6。

## ❌ 不支持（负结果）

- **「本项目的描述比外部大模型好」——不支持。** 视觉四维好/坏：
  `qwen3.8-max` **113/3**、`GLM` **105/10**，均优于 `L` **89/12**、`D` **85/19**。
- **「RL 有效」——不支持。** 10 个 run 没有一个显著超过 SFT，学习率 5e-5 那批显著更差。
- **「描述监督提升类别」——不支持。** 七字段题面上三个种子**全部显著更低**。
- **「L 的描述最好」——不支持。** L 六维合计排最后，且**完全由格式一维造成**；
  去掉格式后它的视觉四维反好于 D。准确说法是「**视觉内容中上，格式合规最差**」。
- **「397B 能力最差」——不支持**（是围栏导致的判分假象）。

## 独立复算情况

本交付的数字**由 CPU 交付整理协作者用四个只读脚本独立复算过**，
与主执行会话的产物**逐项一致**：类别 8 模型全对、枚举 8×5 维全对、方向三分列全对、
请求日志 144 = 132 ok + 12 error、复算费用 4.9034 元、36 张图 sha256 36/36 一致、
冻结题面 sha256 六份文件全部一致、CPU 契约 6/6 通过。

**两条如实披露的发现**：
1. `部署原型/指纹.json` 对 `部署报告.md` 与 `简历事实句_部署原型.md` **已过期**
   （指纹登记 01:27，这两份文档 01:50 又更新过）—— **不是篡改，是登记后又被改**。
2. 核对期间主会话的枚举汇总脚本与分片 JSON 形状**不一致**（**4 片扁平 / 2 片分组**），
   按当时脚本读法只能读到 **96/288**（= 两片分组的 48+48）；
   主会话已在 12:49 当场修复。**修复后的成品与本协作者逐格直接对比：差异 0 / 240 格。**
