## 一、研究问题

半导体晶圆在电性测试后产生 BIN 图：**绿色 = 合格 die，红色 = 失效 die，其余为背景**。
产线上的判读问题是：**这张图的失效格局属于哪一类缺陷？以及，能不能用一句人能看懂的话把它描述清楚？**

本项目只用**公开数据**（WM811K / LSWMD）研究两个可测量的子问题：

| 编号 | 问题 | 度量 |
|---|---|---|
| **Q1** | 固定 9 类（Center / Donut / Edge_Loc / Edge_Ring / Loc / Near_full / Random / Scratch / none），模型能否判对类别？ | 准确率 / Macro-F1 |
| **Q2** | 模型给出的中文描述，**是否与图上真实格局吻合**？ | 六维枚举（形态/位置/遗漏/断言/格式/方向） |

以及一个工程问题：

| **Q3** | 这套能力**能不能落成一个真的服务**（HTTP、结构化输出、可审计）？ | CPU 契约测试 + 真实 HTTP 回放 |

**明确不在范围内**（`AGENTS.md` §18.3）：SEM 图、FDC 时序、根因推断、多轮问答、检索训练、参数网格搜索。

## 三、方法

### 3.1 两个同基座模型（**同一个 Qwen3.5-9B，同数据，只改监督答案**）

| 模型 | 训练监督 | 用途 |
|---|---|---|
| **`L-N3072-3407`** | **只给 `defect_class`**（9 类） | 类别专用模式 |
| **`D-N3072-3407`** | 给 `{defect_class, morphology(←教师 shape), caption_zh}` | 描述模式（部署用） |

这是本项目**最干净的一组对照**：同基座、同 3072 图、同题面模板、同解码参数，
**只改监督答案**。实测差距 0.1667 → 0.8889（见第五节）。

### 3.2 描述事实的评法（**这是本轮方法上最较真的一件事**）

**上一轮用自由文本正则给描述打分，有三个缺口**（`当前部署验收与口径.md:9-15`）：

1. `CLEAN_LEAD` 把「**部分支持**」列成干净；
2. `classify()` 在**没找到问题词时默认干净** → 负向维度只写「有」「轻微」会被错误放行；
3. `cell()` **有结论字段时忽略证据文本** → 证据明明与图不符也不进问题识别。

→ **上一轮的 81.0% / 89.8% 不能当正式描述准确率，本轮不再引用。**

**本轮改为冻结枚举**，并在复核前回归 **20/20** 才允许开工（`复核schema_冻结.py`）：

- 六维统一四值：`SUPPORTED`（好）/ `PARTIAL`（部分或轻微）/ `CONTRADICTED`（坏）/ `UNCERTAIN`（判不了）；
  另有 `MISSING`（字段为空）与 `NEEDS_REVIEW`（归属不明）；
- **`SUPPORTED` 恒为「好」**：负向维度写「无」也是 `SUPPORTED`；
- **方向拆成两列**：`applicable`（该不该有方向）与 `verdict`（含 `NO_ANSWER`）——
  **「不适用」「未答」「可评且吻合」必须分开算**；
- **`MISSING` 不算正确，`NEEDS_REVIEW` 不默认通过。**

### 3.3 八个模型怎么放在一起比

| 模型 | 来源 | 是否见过本项目训练标签 |
|---|---|---|
| `L-N3072-3407`、`D-N3072-3407` | 本项目租机 GPU | **见过 3072 图标签** |
| `Base`（Qwen3.5-9B 原生） | 同环境零样本 | 没见过 |
| `qwen3.8-max-0902`、`qwen3.5-397b-a17b`、`qwen3-vl-plus`、`kimi-k3` | 阿里百炼 API | 没见过 |
| `GLM`（WorkBuddy 客户端） | 外部客户端 | 没见过 |

**⚠️ 这不是「同预算下的模型家族对比」**：学生看过领域标签，外部模型是零样本。
本轮的类别差距**不是训练预算对齐的因果对比**。

## 四、工程落地（Q3）

部署的是一个**真实 HTTP 服务**（`wafer_service.py`），不是 notebook：

| 设计点 | 做法 |
|---|---|
| 结构化输出 | 冻结七字段 JSON；不合 schema **不修补**，标 `needs_review` 并**保留原答** |
| 可审计 | 每个响应同时返回 `raw_answer`（逐字节保留）与规范化后的 `result`，另列 `format_changes` |
| 输入校验 | 非 PNG / 非红绿调色板 / 尺寸不符 → 拒绝 |
| 权重自校验 | 服务启动时校验基座分片与 adapter 的 sha256 |
| 无依据断言 | caption 里出现图上不可验证的度量/尺寸 → 进 `needs_review` |

**独立复算的实测数字**（`部署服务复算.md`，36 图真实 HTTP 回放）：

| 项 | 值 |
|---|---|
| HTTP 200 | **36 / 36** |
| 类别正确 | **25 / 36 = 0.6944**，Macro-F1（固定 9 类）**0.6756** |
| `needs_review` | **19** 条（其中 19 条因「模型标了不确定」，1 条因未支持的度量断言） |
| 延迟 p50 | **4.18–4.22 s**（随百分位口径） |
| 延迟 p95 | **4.88–5.38 s**，max **5.48 s** |
| 模型加载 | 9.93 s |
| 峰值显存 | **17.88 GiB** |
| 服务实际改动过的字段 | **只有 `clock_direction` 的 JSON 类型规范化（16 次）** —— 把字符串 `"null"` 规范成 JSON `null`，**原答逐字节保留** |

**CPU 工程契约测试**：本协作者**实跑** `test_cpu_contract.py` → **6 / 6 通过**
（调色板与存在性、非法输入拒绝、序列化保原答、坏结构不修补、无依据断言可审计、重复键拒绝）。

> **边界**：「HTTP 通过」≠「内容正确」；「部署运行成功」≠「业务能力相当」。
> 上述时延是**同客户端 HTTP 提交到完整响应**，**不是外部网络时延**。
> `D` 的 adapter sha256 = `babf37ecced78d37…`，与学校 5090 上记录的**逐位一致**（两处独立文档互证）。

## 六、支持 / 不支持 / 未测（**必须一起读**）

### ✅ 被本轮证据支持的

| 主张 | 证据 |
|---|---|
| 在**公开标签**上做监督微调，能显著提升 9 类晶圆图缺陷判读 | `Base` 0.1667 → `L` 0.8889（同基座同题面，36 图）；84 图上 77/84 |
| 类别专用监督（L）在类别上**远高于**零样本外部模型 | L 0.8889 vs 最好外部 `qwen3.8-max` 0.5278 |
| 冻结枚举能把「格式失败」与「内容错误」分开 | 397B 严格 0 → 围栏诊断 22.2% |
| 该项目的能力能落成**可审计的 HTTP 服务** | 36/36 HTTP 200；CPU 契约 6/6；原答逐字节保留 |
| 描述事实可以用**不依赖自由文本正则**的方式评 | 枚举 schema 冻结并回归 20/20；本协作者独立复算逐维一致 |

### ❌ **不被**本轮证据支持的（负结果，照实写）

| 主张 | 为什么不支持 |
|---|---|
| **「本项目小模型的描述比外部大模型好」** | **不支持**。视觉四维：`qwen3.8-max` 113 好/3 坏、`GLM` 105/10，**都优于** `L` 的 89/12 与 `D` 的 85/19 |
| **「RL 有效」** | **不支持**。10 个 RL run **没有一个显著超过 SFT**；学习率 5e-5 那批**显著更差**（少答对 14–22 题）。准确说法是「**没有观察到提升**」 |
| **「描述监督能提升类别识别」** | **不支持**。类别题面不显著，**七字段题面上三个种子全部显著更低**；标签对照组反而更好（单种子层面，有边界） |
| **「L 的描述最好」** | **不支持**。L 六维合计**排最后**，而且**完全由格式一维造成**；去掉格式后它的视觉四维反好于 D |
| **「格式差无所谓」** | **不支持**。格式是交付可用性的一部分；只是**不该和视觉事实混在一个比例里** |
| **「`qwen3.5-397b-a17b` 能力最差」** | **不支持**。严格 0 是围栏造成的判分假象 |
| **「部署运行成功 = 业务能力相当」** | **不支持**。实测另说（见上表） |

### ⚪ 未测 / 未做（**不填 0、不填满分**）

1. **真人 gold 复核** —— **本项目已决定不做，真人栏永久留空**。全部描述结论是**模型自查**。

## 九、局限（**读结论前必须知道**）

1. **36 图是开发集**（val84 每类 2 张 + dev18，`Near_full` 仅 4 张），**不是新盲测卷**；
   旧 84 图成绩**不能换分母**用在这里。
2. **学生见过领域标签，外部模型是零样本** —— 类别差距**不是**训练预算对齐的因果对比。
3. **描述复核是模型自查**，执行者继承编排会话上下文，**不是人工 gold**；
   **真人栏永久留空**。
4. **六维分项不是独立样本**：36 图 × 5 维来自同 36 张图，
   **不能当 180 个独立观测，更不能把某几项比例说成描述准确率**。
5. **格式不是视觉事实**，与形态/位置语义不同，**不可加总**。
6. **外部模型后端标识、采样参数、后台注入未知**；`qwen3-vl-plus` 是滚动别名。
7. **四个候选是事前锁定的**，好坏都报，**不按榜单挑弱模型替换**。
8. **两个模式不要拼**：`L` 是类别模式、`D` 是描述模式，
   **不能把两者的最优结果拼成「一个模型」的成绩**。
9. **「运行成功」与「能力相当」是两件事**。
10. **本项目零人工环节**：所有「人工」栏位（评审表、gold）**全空**，报告保持草稿状态。
