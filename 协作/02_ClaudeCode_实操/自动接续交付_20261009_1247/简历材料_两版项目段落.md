## 一、算法 / 多模态版（项目经历段）

**晶圆 BIN 图缺陷判读的多模态模型微调与评测口径建设**（个人项目 / 公开数据）
`Qwen3.5-9B` · `LoRA SFT` · `WM811K` · `冻结枚举评测` · `同基座对照`

**动作**
- 基于公开数据集 **WM811K** 的 5904 张抽样子集（固定种子 3407，`train/val/test = 4721/594/589`，**跨划分 lot 交集为 0**），
  按公开类别分层抽出 **3072 张**训练池（训练池 2171 lot 与评测 102 图 lot 交集为 0）。
- 在同一基座 Qwen3.5-9B 上用 **LoRA** 微调**两个同输入、同题面、只改监督答案**的模型：
  `L` 只监督类别标签，`D` 监督类别 + 形态 + 中文描述 —— **逐图输入完全相同**（`D_L输入相同 = true`）。

**系统能力**
- 建了**固定 36 图（开发集）的八模型同题对照**：本项目 `L`/`D` + 原生基座 + 四个商用 API 模型
  （`qwen3.8-max-0902`、`qwen3.5-397b-a17b`、`qwen3-vl-plus`、`kimi-k3`）+ 外部 GLM，
  固定题面 sha256、固定解码参数，日志留痕可复算。
- 把"描述是否与图相符"的评法**从自由文本正则改成冻结枚举 schema**：
  六维四值（SUPPORTED / PARTIAL / CONTRADICTED / UNCERTAIN / MISSING / NEEDS_REVIEW）+ **方向拆成两列**，
  改口径后先跑 **20/20 回归**才开工。

**业务用途**
- 晶圆 BIN 图判读的核心问题是"缺陷格局是什么、像不像已知类别"，
  而质检沟通还需要一句人能读的中文描述 —— 本项目把这两件事**分开建模、分开评测**，
  以回答"该不该给描述监督"这个工程取舍。

**实测结果**（全部为**固定 36 图开发集**，非盲测卷）
| 指标 | 实测值 |
|---|---|
| 同基座只换监督：Base → L | **0.1667 → 0.8889**（+72.2 pp） |
| L vs 最好的零样本外部模型（qwen3.8-max） | **0.8889 / 0.5278** |
| 描述监督模型 D 的类别准确率 | **0.6944**（低于 L） |
| 84 张开发验证集上 L | **77/84 = 91.7%**，九类 Macro-F1 **0.9227** |

**负结果（照实写，这是本轮最有信息量的部分）**
- **"本项目的描述比外部大模型好"——不支持。** 冻结枚举下视觉四维 好/坏：
  `qwen3.8-max` **113/3**、`GLM` **105/10**，均优于 `L` **89/12**、`D` **85/19**。
- **"描述监督能提升类别"——不支持。** 在七字段题面上三个种子**全部显著更低**。
- **"L 描述最好"——不支持。** L 六维合计排最后，且**完全由"格式"一维造成**；
  去掉格式后它的视觉四维反而好于 D。准确说法是「**视觉内容中上、格式合规最差**」。
- **"模型更懂图"之外的差距**：与外部模型的分数差**不是对齐预算的因果对比** ——
  本项目模型见过领域训练标签，四个 API 模型是**零样本**。

**个人边界**
【待补】本人在上述工作中的具体承担范围（本项目由多角色协作流程执行，项目文档记录的是角色分工而非个人分工）。
项目全程只用公开数据，**未使用任何公司内部数据，未做产线部署**。

## 二、AI 应用工程版（项目经历段）

**晶圆判读模型的 HTTP 推理服务化与可审计交付**（个人项目 / 公开数据）
`HTTP 服务` · `schema 校验` · `审计留痕` · `性能实测` · `预算守卫`

**动作**
- 把微调模型包成**真实 HTTP 推理服务**（`wafer_service.py`），
  设计三条硬约束：**输入合法性校验**、**JSON schema 校验**、**原答逐字节保留**。
- 关键取舍：**schema 不合不修补** —— 坏结构一律标 `needs_review` 并保留原答，
  只把"服务实际改过什么"单列成 `format_changes`（实测只有 `clock_direction` 的 JSON 类型规范化，16 次）。

**系统能力**
- 该服务具备：请求校验 → 推理 → schema 校验 → `format_changes` 审计 → `needs_review` 复核标记 → 结构化响应，全链路可回溯。
- 在**固定 36 图**上做**真实 HTTP 回放**（非单元测试），并另跑一套 **CPU 工程契约测试**（与 GPU 解耦，可在无卡机器上验）。
- 对照实验侧同样做了工程化：**20 元硬预算守卫**（在途按 `max_tokens` 预留、完成按实际 `usage` 结算），
  合同里写死"**每图一次请求、客户端重试 0、失败原件保留、不重新调用**"，避免重试带来的选择偏差。

**业务用途**
- 工业质检场景里，模型输出的**可审计性**和准确率同等重要：
  产线需要知道"这条结果是模型原样给的、还是服务改过的"，也需要一个明确的"这条我不确定、请人工看"的标记。
- 本项目把这两点做成了**默认行为**而不是后补开关。

**实测结果**（**真实 HTTP 回放，36 图**）
| 指标 | 实测值 |
|---|---|
| HTTP 返回 | **36/36 返回 200** |
| 类别判对 | **25/36**，固定 9 类 **Macro-F1 0.6756** |
| `needs_review` 标记 | **19** 条 |
| 时延（同客户端提交→完整响应） | **p50 ≈ 4.2 s**、**p95 ≈ 4.9–5.4 s**、max ≈ 11.6 s |
| 峰值显存 | **17.88 GiB** |
| CPU 工程契约测试 | **6/6 通过**（另有一次本交付内的独立实跑复现，同样 6/6） |
| API 对照预算 | 4 模型 × 36 图 = 144 请求，实付 **≈4.90 元 / 20 元上限**（132 成功 + 12 连接层失败） |

**负结果与不达标项（照实写）**
- **"HTTP 通过"≠"内容正确"**：36/36 都返回 200，但**只有 25/36 判对**（且这是描述模式模型 D 的成绩，不是 L 的 91.7%）。
- **12 条连接层失败未补齐**：为保证"不做二次调用"的对照纪律，失败原件保留、未重发。
- **时延是"同客户端提交→完整响应"**，**不是外部网络时延**；百分位口径不同会得到不同数字（p50 在 4.18–4.22 s 区间、p95 在 4.88–5.38 s 区间）。

**个人边界**
【待补】本人对该服务的设计与实现承担范围。
服务只跑在**获准的租用实例**上，**未做公网发布、未做产线试点**；
**"已产线部署"不得写**。GPU 计费分钟与租机人民币实耗在仓库内**无账单可核，不代填**。

## 三、3 分钟讲述稿（口语，可直接背）

> 大家好，我讲一个我做过的项目：用公开的晶圆图数据研究"多模态模型能不能读懂晶圆缺陷图，并且说明白话"，
> 最后把它做成一个能审计的 HTTP 服务。

**（0:00–0:40 背景与问题）**
晶圆在制造过程中会在表面留下缺陷，表示成一张 BIN 图 —— 就是一个格状的热力图。
业界公开数据集 WM811K 把它分成九类，比如环形、中心、划痕、随机等等。
我想回答的问题很具体：**基座模型本来不会判这九类，那给它标签监督能不能学会？**
以及更进一步：**让它顺便用中文描述一句"这张图长什么样"，会不会让它判得更准？**

**（0:40–1:30 做法）**
我用的是 Qwen3.5-9B，从 5904 张的公开子集里按类别分层抽了 3072 张来微调，LoRA。
这里我做了我认为整个项目最重要的一个设计：**同基座、同数据、同题面、同解码参数，只改监督答案**。
第一个模型只给类别标签，第二个模型给类别 + 形态 + 中文描述。**逐张图的输入是完全一样的。**
这样"描述监督到底有没有用"就变成一个干净的对照，而不是拿两个不同模型来比。
对照集是固定的 36 张图，另外我拉了四个商用大模型和 GLM 一起做同题对照。

**（1:30–2:20 结果，先讲正的后讲负的）**
结果是：**基座完全不会，16.7%；只加类别标签就跳到 88.9%**。
在另一个 84 张的开发集上，类别模型是 77/84，91.7%。
但接下来是更重要的部分 —— **负结果**。
第一，**加了描述监督，类别准确率反而掉了**，从 88.9% 掉到 69.4%。
第二，我原本以为我们自己的中文描述会比较强，**结果不是**：
把描述按六个维度拆开打标之后，外部模型在视觉四个维度上都比我们好。
第三，我一开始看汇总表发现"只给类别标签的那个模型描述分最低"，
**但拆开一看完全不是这么回事** —— 它排最后是因为**格式**那一项扣光了，
把格式去掉，它的视觉内容其实是中上水平。
所以这个项目的结论不是"我们的模型全面更好"，而是**"类别能力"和"描述能力"是两件可以实测分开的事，
而且格式合规必须单独一列算，否则会得出完全错误的结论。**

**（2:20–3:00 落地与边界）**
最后我把它做成了一个真实的 HTTP 服务，36 张图真实回放，**36 个请求全部 200，判对 25 张**，
p95 大概 5 秒，显存峰值 17.9 G。服务有三个我坚持的设计：
**原答逐字节保留**、**schema 不合不修补而是标 needs_review**、
**把服务实际改过的字段单列成审计项**。
因为工业质检里，**"这条是模型原样给的还是服务改过的"本身就重要**。
我也应该说清楚边界：**数据全部是公开数据，没有产线部署**；
描述的部分**是模型自查，不是人工金标**，这一轮我们**决定不做真人复核**；
另外我们自己的模型见过领域标签、外部模型是零样本，**所以那个分数差不能当成"我们更强"**。
