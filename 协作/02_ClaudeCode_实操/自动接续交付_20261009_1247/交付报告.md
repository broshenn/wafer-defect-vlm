## 三、核对中发现的两处问题（**如实披露，均已定性，均非造假**）

### 1. 指纹登记过期（不是篡改）
`部署原型_20261009_0120/指纹.json` 登记的指纹对应 **01:27:05** 的版本，
而 `部署报告.md` 与 `简历事实句_部署原型.md` 的 mtime 是 **01:50:39**。
→ 含义是「**登记之后这两份文档又改过**」，**不是内容被偷改**。
→ 已在 `独立核对结论.md` 明确写成「快照过期」，并在本次交付中保留原始时间证据。

### 2. 枚举分片形状不一致（在途事故，已被主会话当场修复）
核对期间发现 6 个复核分片**混用两种结构**：**4 片扁平（分片1/3/5/6）+ 2 片分组（分片2/4）**，
而当时的汇总脚本只从 `答案集` 取答案 → 对 4 片扁平读出 0 行，
**按修复前读法只能得到 96/288**（= 分片2 的 48 + 分片4 的 48），
而正确覆盖应为 **288/288**（8 模型 × 36 图）。
主会话已于 **12:49** 修复（脚本 mtime 12:49、体积 8237 → 9350，新 `extract()` 两种形态都吃），
并重新产出 `描述对照_枚举.json`。

**当前有效性以逐格直接对比为准**：本协作者把独立复算结果与主会话**修复后的成品**
`描述对照_枚举.json` 做 **8 模型 × 5 维、补齐 0 计数共 240 格**的直接比对 →
**差异条数 0，结论「一致」。**

→ 本协作者在独立脚本里对**两种形状都做归一化**，并对 `(sample_id, 盲号)` **去重**
（首版未去重曾得 42/36 的虚高覆盖，已修正），因此不受该事故影响。
→ 脚本内那个 `96` 是对**修复前**读法的静态只读模拟，**属历史记录**；
脚本注释已明确标注，**避免把历史模拟误读成对主会话当前脚本的指控**。

> **这两条都写进交付，不做「看起来全绿」的处理。**

## 四、数据资产：一处必须更正的口径

`5904 / 4292 / 3072 / 1200` **不是四批并列数据，而是一条包含链**：

```
WM811K（抽样 5904）→ train+val 5315 → 旧 SFT train 4292 → 本轮训练池 3072 → 「训练缺口 1200」⊂ 3072
```

**关键更正**：`执行总指令.md` 与 `包说明.json` 把 1200 写成「与 3072 并列」，
但独立审计实测 **`1200 ∩ 3072 = 1200 / 1200`** —— 它**整批落在已训的 3072 之内**，
**不得与 3072 相加计作资产**。

**质量分账（1200，未入训）**：A 严格七字段机械合格 **556** / B 可解析不合 schema **294** / C 纯文本 **350**。
**三档都不能当训练 gold** —— 「保存完整」≠「全部可入训」。

**已从「未测」移出**：5904 全库的**图片内容级去重**已在阶段 2 实测 —— 唯一 sha256 **5875**、
**28 组重复 / 29 张冗余**；训练 3072 个 ID 对应 **3060** 个独特 PNG sha256。
**仍属未测**的是「重复图之间的语义关系」（是否同一物理晶圆）。

## 七、自纠：本协作者自己犯过并已改正的错

1. **误引失败类别清单**：曾在项目说明里写「失败类别见 `AGENTS.md` §8」。
   复核后确认：**`AGENTS.md` §8 是训练计划**；失败类别清单确实存在，但在 **`docs/LIMITATIONS.md` §8**
   （「已修复但值得记录的缺陷，均为"静默产生貌似合理结果"类型」）。
   → 已改正为该处引用，并把该节条目列进 §8.1 作同源清单，同时保留自纠说明（两份文档都编到 §8，正是最容易混用的地方）。
2. **价目表先用错**：首版 `机械核对.py` 用了猜测价目（算得 6.231 元）。
   → 改为读 `百炼对照.py` 的 `MODELS` 与官方价目页后复算 **4.9034 元**，与报告一致。
3. **解析语义混用**：首版把「去思考前缀」和「去围栏」混在一起，导致 Base/L 的严格解析数为 0。
   → 拆成 `parse_strict` / `parse_diag` 两个函数后修正。
4. **覆盖率虚高 42/36**：分片里分组条目与扁平副本是同一批答案，首版重复计数。
   → 加 `(sample_id, 盲号)` 去重后修正为 36/36。
5. **哈希误报**：合并哈希初判「不一致」，实为登记值用**摘要字节**拼接、我用十六进制字符串拼接。
   → 已核实并记录该口径差异，**不是篡改**。
6. **`资产与哈希核对.py` 写出 `.md` 的那段引用了一个不存在的键**（`图目录.复算合并sha256`）——
   我 12:49 把 `.json` 的键改成带口径后缀（`…(digest字节口径)` / `…(hex字符串口径)`）时**没有同步改 `.md` 段**，
   于是 `.json` 是新的、`.md` 停在 12:48，**脚本此后一跑就崩**。
   → **12:55 复跑四个脚本时被我自己发现**（ExitCode 1 / KeyError）。已修正键名，
   并把两个口径的值**都打印出来**、明确写出「hex 口径与登记值不同属正常，不是错误口径」。
   修正后 `.md` 已重新生成，与 `.json` 一致。
   → 教训：**"交付时跑通过"不等于"现在还能跑"** —— 封包前必须重跑每一个脚本，不能只看文件在不在。
