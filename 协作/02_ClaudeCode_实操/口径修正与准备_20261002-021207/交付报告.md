### 1.5 提交前发现：Codex 的 B43 指出我角度工具的测试写错了（已修）

**[事实]** 我准备提交时，`踩雷记录` 里出现了 Codex 新写的 **B43**：
角度工具的稳定性测试**保持 `dr/dc` 不变、只改圆心**，而函数内部又是"圆心 + 偏移"生成缺陷点 ——
**点和圆心一起平移**，测到的是**平移不变性**，不是"固定缺陷点下圆心漂移的稳定性"。

**[事实] 我在本机逐位复现了 Codex 的固定点用例**（72×72，点固定在 (36,46)，圆心 (36,36)，d=10 格）：

| 圆心行漂移 | 角度 | 扇区 |
|---|---|---|
| 0 / ±1e-12 格 | 90.0000000000° | 4 |
| ±1e-9 格 | 89.9999999943° | 4 |
| **+1e-6 格** | **89.9999942704°** | **3 ← 翻了** |

**与 Codex 给的数字一致。**

**[解释] 并且后果比"测试写错"更深一层**：这是**单位不匹配**。
点距圆心 `d` 格、圆心漂 `δ` 格 → 角度改变约 `(δ/d)·(180/π)` 度。
要让容差 `τ` 度真挡住 `δ` 格，需 `d > δ·(180/π)/τ`。
代入默认值 `τ=1e-6°`、`δ=1e-6 格` ⇒ **需 d > 57.3 格**，
而本库晶圆半径通常只有 **12–36 格** —— **默认容差对典型晶圆几乎没有保护作用**。

**[改动]** `angles.py` 新增 `guard_tolerance_deg()` 与 `sector_of_point()`：
容差改为**逐点**计算（`max(基础容差, (δ_px/d_px)·180/π)`），圆心不确定度
`center_uncertainty_cells` 改为**必须显式声明**的参数（默认 0 = 声明圆心精确，不是自动推断）。
`angle_config.json` 把上述推导、实例与"默认容差无保护"的结论一并写进配置。

**[语义写准，不靠放大容差凑绿]** 容差 = 漂移 δ 时的**最坏**角度偏移，
所以保证范围是"漂移**严格小于** δ"。漂移正好等于 δ 时由构造落在边界上 —— 这是定义使然。
**我没有放大容差**去让那条测试变绿；改为在 δ 的 50% 与 99% 处验稳定（δ = 0 / 1e-6 / 1e-3 三档全过）。

**另存文档**：`角度工具_固定点测试与适用范围.md`（含解析式、适用范围与**不**适用范围）。
