## 更正 1：那不是单卡 —— 是六卡分片

**原报告说**：使用了「1 张 A100 80GB」。
**实际**：进程启动后打印 `可见 GPU 6`，`hf_device_map` 把模型铺满 **0–5 全部六张卡**。

```
hf_device_map: {'model.visual': 0,
                'model.language_model.embed_tokens': 1,
                'model.language_model.layers.0': 1, ... 'layers.2': 1,
                ... 'layers.3'..'layers.10': 2,
                ... 'layers.11'..'layers.18': 3,
                ... 'layers.19'..'layers.26': 4,
                ... 'layers.27'..: 5}
```

**根因是我脚本的 bug**：`os.environ["CUDA_VISIBLE_DEVICES"] = a.gpu` 写在 `import torch` **之后**，
CUDA 在首次调用时读取可见设备列表，此时设置已经无效。

**连带后果**：因为 `device_map: auto` 会铺满所有可见卡，训练期间**其中包含 GPU 3 —— 那张卡上还有他人的任务**
（PID 4094123，55.7 GB）。所以：

- 不能说"没有使用他人占用设备"；
- **是否对他人造成影响，未测**；我也没有终止或修改任何他人进程。
- 这是**单进程模型分片**，不是 DDP；有效 batch 仍为 4，这一点原报告没说错。

**已在新一轮修复**：`CUDA_VISIBLE_DEVICES` 改由**父进程 shell 在 python 启动前**设置，并在脚本里
断言 `可见 GPU 数 == 1`、`world_size == 1`。新日志里写的是 `可见 GPU 数 = 1`。

## 更正 2：4.35 GiB 不是单卡峰值

`memory(GiB) 4.35` 是 trainer 打印的字段，不是整个 9B 模型在单卡上的峰值。
六卡分片下**每张卡各拿一份分片**，所以任何"单卡峰值"的说法都不成立。

**新单卡实测**（本轮，本人进程 `torch.cuda.max_memory_allocated`）：

| run | allocated | reserved |
|---|---|---|
| A1 seed3407 | 18.62 GiB | 18.79 GiB |
| A2 seed3408 | 18.62 GiB | 18.79 GiB |
| A3 seed3409 | 18.62 GiB | 18.79 GiB |
| V 验证套件 | 17.86 GiB | — |

**旧多卡的总峰值没有保存 → 写「未测」**，不用别人的显存数字当自己的。

## 更正 4：基座 dev18 表写错了

原报告逐条表把基座的两条 `none` 标成正确。**实际两条 `none` 都预测成 `Loc`，都错**。

**实测逐条**（`V_基座_dev18_原答.jsonl`）：18 条里**预测 `Loc` 16 条、`Random` 1 条、`none` 1 条**。

**三个正确的样本真值是：`Random` ×1、`Loc` ×2** —— 不是 1 Random + 2 none。

## 更正 6：train_loss 不是一条曲线

`smoke 0.3213 → main 0.1613` 是**两个独立起点、不同数据规模**下的**平均** train_loss，
**不能当成同一条学习曲线的两端**。真正的逐步曲线在 `logging_smoke.jsonl` 与 `logging_main.jsonl` 里。

（Codex 独立复算给出 main 首步 loss ≈ 0.406、末步 ≈ 0.031，与逐步日志一致。）

## 更正 7：训练内的 eval 是「已见样本」诊断

`eval_dataset` 明确是 **`sft_a_smoke_20.jsonl`**，它是 `train_180` 的子集，**训练时已经见过**。
