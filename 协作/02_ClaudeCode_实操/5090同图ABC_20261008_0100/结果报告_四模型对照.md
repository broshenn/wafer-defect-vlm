## 四、关键观察

1. **A 组（只类别）最好，而且合规满分。** 说明这张题的九类识别
   在 356 图 1 epoch 下，"只监督类别"是效率最高的信号。
2. **加几何（B）、加描述（C）都降低了类别准确率**，其中 C−A 显著。
3. **B 的附加几何 102/102 条全部产出、C 的 caption 102/102 全部产出**，
   格式上模型学会了输出附加字段。
   **但附加字段的事实一致性没有独立 gold，列未测**（见下）。
4. **S0 的 0 分是格式而非能力**——这正是合同要求保留"严格主分 + 围栏诊断"
   两条路径的价值。**不把解析失败说成没有描述。**

### 4.1 B 组的辅助字段本身有问题（重要）

B 的几何字段是**纯 Python 确定性计算**的（`prepare_data.py:103` →
`calculate_static_features`），不是模型生成的。**但"确定性"不等于"正确"。**

`radial_zone` 的定义是 **`_zone(质心半径)`——质心所在区，不是缺陷所在位置**。
对任何关于晶圆中心对称的图案，质心落在圆心，于是标签**靠算术塌缩成 "center"**。

**本项目自己的审计脚本早就记录了这个缺陷**
（`archive/local-skeleton/tools/radial_zone_audit.py` 开头）：

> 冻结基准里 `Edge_Ring` 的中位质心半径只有 0.063，**83.7% 的样本落进 "center" 桶**。
> 模型对边缘环答 "edge" 反而被判错。

**在本次 356 张上的独立复算：**

| B 的 `filtered_defect_centroid_radial_zone` | 条数 |
|---|---|
| **center** | **313（87.9%）** |
| middle | 39 |
| edge | 4 |

**Edge_Ring 39 条，100% 被判 `center`**；而这些图的 `mean_radius_r` 中位
= **0.9421**、`defect_extent_r` 中位 = **2.0320**，远超判 edge 的 0.72 阈值。

**这对 B 的结果有解释力**：B 教给模型的辅助字段 88% 塌缩为 `center`、
对边缘环 100% 标错，几乎没有可用的空间信息。

**但这是解释，不是已证明的机制。** A/B/C 同时改变了监督内容，
本轮**无法**把"字段误导"与"监督 token 变多"分开；且是单种子开发集。

三组"额外信息"的性质本就不一样：

| 组 | 额外信息 | 来源与质量 |
|---|---|---|
| A | 无 | 公开原标签（`label_source=ground_truth`） |
| B | 几何 | **Python 确定性计算**，但 `radial_zone` 系统性算错 |
| C | 描述 | **模型生成**（旧158 + GLM107 + 接续49 + GPT42 混合来源），不是 gold |

## 五、未测与限制（严格区分）

- **附加几何/Caption 的事实一致性**：没有独立依据，**列未测**。
  训练规则分不替代事实能力。
- **B 的语义边界**：B 的字段已改名（`filtered_defect_centroid_radial_zone` /
  `filtered_defect_die_ratio`），表示**滤孤点后全部红点质心**的径向区与
  **滤后计数/有效die** 的比例，**不是主要缺陷簇的位置或占比**。
  本轮**不能**解释成"主要簇几何的价值"。
- **Near_full 只有 4 条**（val84 中），逐类指标对这一类不稳定。
- **单种子**：无种子波动，配对差区间只反映样本抽样不确定性。
- **A100 的历史成绩不可比**：D1 描述 SFT 的 99.0% 七字段合法率是**不同题面、
  不同硬件、不同 torch 环境**下的数，**不能拿来解释本轮 A/B/C 的差异**。
- **本轮不重跑 D1、不加种子、不做 DDP、不启动 RL。**

## 七、本轮我自己的失误（如实记录）

1. **传错脚本路径**：上传的 `eval_abc.py` 里还是 `/WS` 别名，
   S0 第一次启动即失败。用 `sed "s#/WS/#...#g"` 修又没匹配上（`R = "/WS"` 后无斜杠），
   改用全量替换才对。
2. **围栏诊断写坏两处**：正则要求围栏在文本开头，但基座输出带 `<think></think>` 前缀
   → 全判 `no_fence`；修的时候又把 `''` 写成了字面量 `chr(39)+chr(39)`（两个单引号）。
   **这是纯离线诊断字段，不影响主分**，已修并离线重算（未重跑 GPU）。
3. **解析器异常顺序**：`except ValueError` 会吞掉 `JSONDecodeError`（它是其子类），
   导致"截断"被判成 `non_finite`；已改用专门异常类。
