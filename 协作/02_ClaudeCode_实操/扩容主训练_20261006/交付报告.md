### 1.4 上传（已获用户"数据也要传"授权）

补传 **1260 张**（2447689 字节 = 2.33 MiB）到学校 `datasets/expand_v2/`。
源端与远端**逐图 SHA256 核对**：

```
逐图 hash 一致 1260（0 不符，0 缺失）
```

外加旧 180 张从 `datasets/images` 复制入同一目录（hash 核对通过），
使 1440 条**全部在同一路径下可读**。manifest 未覆盖。
服务端四档清单已另存并按学校真实路径重写（公开版用 `/WS` 别名）。

### 1.5 【必须记】上传后立刻发现并修掉的一个数据路径缺陷

首次探针日志里出现 `PIL.UnidentifiedImageError`，且 **1440 行里恰好 180 行编码失败**。
定位：服务端 1440 清单把**全部**行都指向 `expand_v2/images/`，
而旧 180 张当时还在 `datasets/images/` —— 失败数 180 = 1440 − 1260，完全吻合。

**修复**：把旧 180 张复制进 `expand_v2/images/`。复验：**1440/1440 路径存在且 hash 一致，
模板编码失败 0/1440**。

**这个缺陷是我造成的**（清单生成时没区分新老图目录），**不是原图有问题**。

## 2. B 部分：主训练

### 2.1 起点与配置

**固定起点为未经本项目训练的原 Qwen3.5-9B 基座**，各 run 新 LoRA。
不看旧 F0/F2，不从它们接着训。

| 参数 | 值 |
|---|---|
| 题面 | 与当前分类 SFT **原样**（206 字符） |
| LoRA | rank 16 / alpha 32 / dropout 0.05 |
| `target_modules` | **显式列表** `["all-linear"]`（字符串会静默失效） |
| 冻结 | `freeze_vit=True`、`freeze_aligner=True` |
| dtype / LR | BF16 / 1e-4 |
| 日程 | warmup_ratio 0.05、**cosine** |
| 其他 | image token 256、max_length 2048、gradient_checkpointing |
| batch | per_device 1 / GA 4，**data_seed 3407** |
| 覆盖 | 统一 1 epoch：步数 = 规模/4 |
| 选择 | **末步预选，不中途按 val 挑最佳** |

依赖保留固定版本（含 `msgspec 0.22.0`）；**未搬旧 Quant/RL 代码**。

### 2.2 隔离

每个任务：**父进程设 `CUDA_VISIBLE_DEVICES`（按 UUID）**，
脚本内断言 `device_count == 1`、`world_size == 1`。六个 run 日志里均记录
`可见 GPU 数 = 1`。**未创建占位进程，未抢他人卡**（GPU 1/3 期间被他人占用，已避开）。

### 2.4 数据呈现（必须算清楚）

| 档 | 行数 | 名义步数 | **实际呈现次数** | 覆盖 |
|---|---|---|---|---|
| 180 | 180 | 45 | 180 | 1.000 epoch |
| 360 | 360 | 90 | 360 | 1.000 epoch |
| 720 | 720 | 180 | 720 | 1.000 epoch |

本轮的 1440 是 **1440 次呈现**，确实全过了一遍。
